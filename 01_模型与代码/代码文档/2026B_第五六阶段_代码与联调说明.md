# 第五、六阶段交付说明：Python 基础版 + 模拟器联调

> **本文记录两件事**：① 第五阶段"Python 实现基础版"的模块结构与职责；② 第六阶段"接入模拟器"的协议实现与**端到端联调结果**。
> **重要声明**：官方模拟器未在本机运行。为打通链路，本队自建了一个 **mock 模拟器**（严格按 `附件1.docx` / `附件2.docx` 的计时与幂等规则实现 4 个端点）。**它是自建复现件，不是官方模拟器**，其结果只能作为**离线验证**，不得冒充正式测试数据。

## 一、目录结构与职责

```text
b26/                        # 机器狗程序包
├── __init__.py
├── locate.py     定位模块   楔形/半平面裁剪/交集/直径/面积/可行域账本 Ledger
├── detect.py     检测模块   观测语义解析（no_signal / near / direction 三态）
├── motion.py     移动模块   虚拟时间账（移动/切换/检测/清除 四笔分开记）
├── search.py     搜索模块   覆盖点集 COVER_7 / COVER_9 + 覆盖证书
├── path.py       路径模块   最近必做调度（nearest）与最近邻排序（order_nearest）
├── comm.py       通信模块   HTTP+JSON、串行、request_id 幂等、断线复用原 ID 重试、全量日志
└── robot.py      主控       把上面六个串起来：搜索 → 发现 → 定位 → 移动 → 清除
b26_mock_server.py          自建 mock 模拟器（4 个端点 + 幂等 + 计时）
b26_run.py                  端到端联调入口
```

| 模块 | 对外接口 | 单一职责 |
|---|---|---|
| `locate` | `wedge_poly(s,θ)`、`intersect`、`diameter`、`centroid`、`area`、`Ledger` | 只做几何，不知道模拟器存在 |
| `detect` | `parse(resp)` → `(类型, 示向度或 None)` | 只做语义解析，不做几何 |
| `motion` | `Motion.move_cost(q)` / `Motion.apply(q)` | 只记账，不决策 |
| `search` | `COVER_7`、`COVER_9`、`coverage_certificate()` | 只给点集与证书 |
| `path` | `nearest(pos, actions)`、`order_nearest(pos, points)` | 只排序，不评估 |
| `comm` | `enter / measure / clear / exit` | 只收发，不含业务判断 |
| `robot` | `Robot(comm, cover).run()` | 唯一做决策的地方 |

**校验**：六个模块互不 import（`robot` 单向依赖其余六个），无循环依赖。

## 二、通信模块的关键实现（对照协议逐条）

| 协议要求（出处） | 实现 | 代码位置 |
|---|---|---|
| 四条指令、POST、`Content-Type: application/json` | `urllib.request.Request(..., method="POST")` + 固定头 | `comm.py` |
| 必填 `arena_id` / `robot_id` / `request_id` | 每次构造 payload 时写死 `arena_id="default"` | 四个方法 |
| **严格串行** | 同步阻塞调用，无线程、无并发原语 | 全模块 |
| **每动作新 ID** | `_next_id(tag)` 自增 | `_next_id` |
| **断线重试复用原 ID 与原内容** | `post()` 内 `for attempt in range(MAX_RETRY)`，**payload 在循环外构造一次**，重试不重新生成 ID | `post()` |
| 同时检查 HTTP 状态码与 `accepted` | `if code != 200 or data.get("accepted") is not True: raise` | `post()` |
| `/clear` 不切换频道 | `clear()` 里 `Motion.apply(pos)` **不传 channel_after** | `robot.clear()` |
| 自行记录日志 | 每请求写一行 JSONL（request_id / path / http_status / request / response / retry） | `_log()` |
| 处理"连不上" | `except Exception` 捕获后重试，超限抛错 | `post()` |

## 三、mock 模拟器复现的协议语义

| 语义 | 实现 |
|---|---|
| 虚拟时间推进 | `/measure`：Δ距离/5 + 切换(0 或 1) + 5 s；`/clear`：Δ距离/5 + 3 s（未发现）或 5 s（成功）；`/enter`、`/exit` 不推进 |
| 频道切换 | **只由 `/measure` 触发**；`/clear` 的 channel 仅作目标频道 |
| 检测三态 | 超距或无源 → `no_signal`；≤5 m → `near`（不返回示向度）；否则 `direction` + `svd_deg`（保留两位小数） |
| 示向度误差 | **按地点固定**：由坐标量化后的哈希决定，落在 ±1°；同址复测读数完全一致 |
| 清除 | ≤20 m 且该频道源存在 → `success` 并删除该源；否则 `no_target_in_range` |
| **幂等** | 同一 `request_id` + 同一请求体 → 返回缓存响应、**不重复推进时间**；不同请求体 → **HTTP 409** |
| 错误 | 路径未知 → 404；缺字段/非法频道 → 400；未 `/enter` → 200 且 `accepted=false` |

## 四、端到端联调结果

**链路**：Python → HTTP 请求 → mock 模拟器 → 返回 JSON → Python 解析 → 决策 → 再次请求 —— **已跑通**。

**覆盖证书**：`COVER_7` 最大未覆盖距离 1000.0 m，裕量 0.0 m，合格 = True。

**5 局连跑**（`python b26_run.py <seed> 7`）：

| seed | 源总数 | 清除数 | 清除比例 | 虚拟总时间 (s) | 平均定位清除时间 (s) | 检测次数 | 清除失败 | HTTP 请求数 |
|---|---|---|---|---|---|---|---|---|
| 7 | 12 | 12 | **1.0000** | 3600.6 | 300.0 | 146 | 0 | 160 |
| 1 | 11 | 11 | **1.0000** | 4009.4 | 364.5 | 144 | 0 | 157 |
| 2 | 16 | 16 | **1.0000** | 4324.8 | 270.3 | 151 | 0 | 169 |
| 3 | 11 | 11 | **1.0000** | 3739.4 | 339.9 | 144 | 0 | 157 |
| 4 | 11 | 11 | **1.0000** | 3815.0 | 346.8 | 150 | 0 | 163 |
| 5 | 14 | 14 | **1.0000** | 4602.7 | 328.8 | 149 | 0 | 165 |

### 四条关键结论

1. **清除比例 5/5 局 = 1.0000**（含 seed 2 的 16 个源），**清除失败次数全为 0** —— 覆盖证书 + "区域直径 ≤ 40 m 才去打"两个机制同时生效。
2. **平均定位清除时间 270—365 s**，与阶段五离线仿真的 295.9 s 同量级，互为独立验证。
3. **一局只需约 160 次 HTTP 请求**。按每行日志约 300 字节估算，**日志体积约 48 KB**，远低于 **2 MB** 上限（安全余量约 **40 倍**）。
4. **程序运行时间（现实）**：本机跑完一局仅约 1—2 秒，相对 **1200 s** 上限有约 **3 个数量级**余量 —— 说明**墙钟不是瓶颈，虚拟时间才是目标函数**（与阶段一的判定一致）。

## 五、接官方模拟器前必须复核的清单

| # | 复核项 | 为什么 |
|---|---|---|
| 1 | 字段名与取值字符串是否完全一致（`measure_result` / `svd_deg` / `clear_result` / `exit_reason`） | 程序按字符串分支，拼错会静默走错分支 |
| 2 | `/clear` 是否真的不改变当前频道 | 我方据此记账；若实际会改，时间账会整体错位 |
| 3 | 同一 `request_id` 重试是否真的返回**第一次的完整响应**且不推进时间 | 我方去重逻辑依赖它 |
| 4 | `remaining_real_duration_s` 的实际取值范围与含义 | 我方用它做墙钟兜底 |
| 5 | `near` 的边界（是否 ≤5 m 含端点）与是否真的不返回 `svd_deg` | 决定分支条件 |
| 6 | 加密日志的实际体积与命名规则 | 关联表 1 的"测试案例编码" |
| 7 | 端口与登录流程 | 默认为 `http://127.0.0.1:2026`，本 mock 用 20260，接入时改回 2026 |

**接入时只需改一处**：`b26_run.py` 里的 `PORT`，或直接调用 `Robot(Comm("http://127.0.0.1:2026", 队号, 日志路径))`。
