### 3.2 图的硬规则

| 规则 | 说明 |
|---|---|
| **图内零中文** | MATLAB LaTeX 解释器**不支持中文**（实测）；中文一律进图注或正文 |
| **图内零结论句** | 禁止「因此…」「说明…」「证明…」「结论：…」 |
| **图内零装饰** | 禁止渐变、阴影、3D、圆角卡片、印章条、无意义箭头、图标 |
| **图内文字仅允许** | 坐标、数学变量、极少量数字、极少量短标签 |
| **红绿冗余** | 红色必配虚线；绿色必配加粗实线（保证灰度可读） |
| **数字唯一性** | 同一数字尽量只在一张图的图内出现（见 04 知识库第十节） |
| **输出** | PDF（主交付，矢量）+ PNG 300 dpi；SVG 为降级通道 |

### 3.3 表（**3 张**）

| 表 | 内容 | 与图的关系 |
|---|---|---|
| **表 1** | 正式测试结果（题面强制四列，Q3 三行 + Q4 三行） | **不画成图**（三行来自三个不同随机案例，柱状图会暗示可比性） |
| **表 2** | 判据与定理汇总（编号 / 内容 / 证据等级 / 出处） | 不重复图 8 的图解式描述 |
| **表 3** | 方案演化矩阵（**只保留真正用于替代决策的行**） | 不重复图 6/7 已表达的 β 一行 |

**原则：图讲结构，表列数据，正文讲推导。同一件事绝不讲三遍。**

### 3.4 图注规则

- 每张图注 **≤ 80 字**；
- 必须说明：**n 值**、**数据来源**、**自建 mock / 官方口径**；
- **不要把正文证明搬进图注**。

## 四、数字与口径规则

| 规则 | 说明 |
|---|---|
| **mock / 官方必须标注** | 同一句子里不得同时出现「官方」与「mock」口径的数字 |
| **n 必须标注** | A 级证据必须标 n（1 / 3 / 6）；**不得作分布性结论** |
| **禁止编造** | 任何数字必须可追到 `03_正式测试与实验事实总表.md` 的出处表 |
| **禁止跨批次比较** | `_work_b26_cmp.json`（8 局）与 `_work_b26_ab3.json`（16 局）**不得混写** |
| **禁止重复解释** | 同一结论不在图、表、正文三处重复 |
| **数学证明必须在正文** | 定理、证明、推导**不得**塞进图内或图注 |
| **图文一致** | 正文数字与图内数字必须同源；**同一实例不要混用两个反例的数字** |
| **正式测试不反推清除率** | 正式测试不显示真值 ⇒ **清除比例的分母不可知** |

## 五、写作风格

**必须**：

- 数学建模论文风格：严谨、简洁；
- 每个公式都有来源（题面 / 推导 / 代码）；
- 每个核心结论都有证据等级；
- 讲具体：**什么模型解决了什么问题，为什么成立，实验验证了什么，还没有验证什么**。

**禁止**：

- 空泛 AI 句式，例如「综上所述，本模型具有较强的鲁棒性和优越性……」；
- 无量化形容词（「效果很好」「显著提升」而无数字）；
- 自定阈值不给依据；
- 夸大创新（不得把「设计提案」写成「已实现」）；
- 为了「好看」删除未认证缺口。


## 八、写作顺序建议

1. **先写第五、六章**（已有初稿，素材最全）；
2. 再写第二、三、四章（问题分析 / 假设 / 符号）；
3. 再写第一、七章（问题重述 / 评价与改进）；
4. 最后写**摘要**（需要表 1 与全部结论）；
5. 附录与 AI 使用详情表放最后。

**每一节写完立即核对**：该节引用的每个数字是否在 `03_正式测试与实验事实总表.md` 的出处表中。
