# 网络流与最小费用流

> **证据等级说明**：〔原文〕= 语料中直接读到的句子/标题；〔归纳〕= 从多篇语料共有的写法中归纳；〔推理〕= 无直接语料支撑、由模型性质推出的判断。

## 1. 模型用途

把系统画成"**节点 + 带容量/费用的有向边**"，让"流"从源点 $s$ 流到汇点 $t$，求最大流量或最小费用。国赛里它解决：

- **运输与调运**：钢管从钢厂经铁路/公路到铺设点（2000B）；
- **物资分配与转运**：DVD 从仓库到会员、原材料从供应商到仓库（2005B、2021C）；
- **供水/管网**：水表层级、漏损分析（2020E 题型判定含"网络流类"〔推理，N02 编目〕）；
- **任务—资源关系**：把指派问题转成流问题（见《指派与匹配问题》）；
- **上下界论证**：多旅行商、巡视组划分的最优性下界（1998B 的证明思路〔原文〕）。

**一句话判断**：当你在写"从 A 运到 B，每条线路有容量上限，运输有单价，求最省/最多的方案"时，就是网络流。

## 2. 题目特征

1. **题眼词**："运输""转运""调运""供应""配送""容量""运力""损耗"。
   - 2021C 原句："确定第三方物流公司（'转运商'）并委托其将供应商每周的原材料**供货数量（'供货量'）转运到企业仓库**"、"每家转运商的运输能力为 **6000 立方米/周**"〔原文，N02 编目〕
2. **有明确的层级/网络结构**：供货点 → 中转点 → 需求点。
3. **给出"单位运费"或"运力上限"表格**。
4. **多阶段流转**：2000B 的"订购—运输—铺设"三段。
5. **要求最大/最小且带容量限制**。

## 3. 数学原理

**来源**：Ford–Fulkerson（1956）最大流算法；最小费用流由 Klein、Jewell、Busacker–Gowen 等建立〔推理，属通用理论〕。

**成立前提**：

1. **网络结构给定**：节点集 $V$、有向边集 $E$ 已知且固定。
2. **容量守恒**：除源汇外，每个节点的流入 = 流出（流量守恒）。
3. **容量约束**：$0\le f_{ij}\le u_{ij}$。
4. **费用线性**：边费用 $c_{ij}$ 与流量成正比——**若费用是凹/凸函数（如运输的规模折扣），标准算法失效**，需要分段线性化或专门的凸费用流算法。
5. **单商品**：所有流可混（多商品流是 NP-hard，需 MILP）。

**核心定理（论文里值得写）**：

- **最大流最小割定理**（Ford–Fulkerson）：最大流的值 = 最小割的容量。这是网络流理论的核心，也是"最优性证明"的利器。
- **流分解定理**：任何 $s$-$t$ 流可分解为若干条 $s$-$t$ 路径上的流与若干环流之和。
- **整数流定理**：容量为整数时，最大流有整数最优解——**这是网络流能直接解整数问题的原因，也是它相对 LP 松弛的巨大优势**。

## 4. 基本公式

**最大流问题**：

$$\max\; v=\sum_{j:(s,j)\in E}f_{sj}-\sum_{j:(j,s)\in E}f_{js}$$

$$\text{s.t.}\quad \sum_{j}f_{ij}-\sum_{j}f_{ji}=\begin{cases}v,&i=s\\0,&i\ne s,t\\-v,&i=t\end{cases}$$

$$0\le f_{ij}\le u_{ij}$$

**最小费用流**：

$$\min\;\sum_{(i,j)\in E}c_{ij}f_{ij}\qquad \text{s.t.}\quad \text{流量守恒},\; 0\le f_{ij}\le u_{ij},\; \text{净流量}=v$$

**最小费用最大流**（2000B、2005B 的做法〔原文〕）：先求最大流 $v^*$，再在 $v=v^*$ 下求最小费用；或用 Busacker–Gowen 逐步沿最短路增广。

**对偶（势函数/节点价格）**：存在节点势 $\pi_i$ 使得 $c_{ij}+\pi_i-\pi_j\ge0$（对无流量的边取等号），这是费用流的"影子价格"。

**运输问题特例**（Hitchcock 模型）：

$$\min\;\sum_{i}\sum_{j}c_{ij}x_{ij}\quad \text{s.t.}\quad \sum_j x_{ij}=a_i,\;\sum_i x_{ij}=b_j,\;x_{ij}\ge0$$

## 5. 参数含义

| 符号 | 含义 | 例 |
|---|---|---|
| $f_{ij}$ | 边 $(i,j)$ 上的流量 | 每周从钢厂 $i$ 运到节点 $j$ 的钢管量 |
| $u_{ij}$ | 边容量 | 转运商运力 6000 m³/周 |
| $c_{ij}$ | 单位流量费用 | 每立方米每公里的运费 |
| $s,t$ | 源点/汇点 | 虚拟总源、虚拟总汇 |
| $v$ | 净流量（总运量） | 总供货量 |
| $\pi_i$ | 节点势/对偶变量 | 节点的边际价格 |

## 6. 建模步骤

1. **识别"流"是什么**：钢管、DVD、原材料、水、任务。
2. **建节点**：所有"可以停留/中转/需求"的点都建节点。
3. **建边与方向**：按题目的物理流向建有向边；双向可走的建两条反向边。
4. **定价与定容**：
   - 费用放 $c_{ij}$（单位量费用）；
   - 容量放 $u_{ij}$（若无限则取充分大或 $\infty$）。
5. **加虚拟源汇**：多个供应点接一个虚拟源 $s$（容量 = 供应上限），多个需求点接虚拟汇 $t$（容量 = 需求量或 $\infty$）。
6. **处理"必经/损耗"**：
   - 损耗率 $\theta$：把边流量定义为**到达量**，或引入折算系数，或用 $f_{\text{到}}=f_{\text{发}}(1-\theta)$——**注意这会破坏流量守恒，通常做法是把损耗折进边的费用或容量**；
   - 必经点：拆点（入点、出点之间加容量下界）。
7. **求最大流/最小费用流**，读出每条边的流量，翻译回业务量。
8. **对偶分析**：用节点势说明哪里是瓶颈。

## 7. 算法

1. **最大流——Dinic 算法**（推荐，最实用）：
   a. 建残量网络（正向边容量 $u-f$，反向边容量 $f$）；
   b. BFS 分层，标出各点到 $s$ 的层号；
   c. 在分层图上 DFS 找**阻塞流**，一次推完所有可行增广路；
   d. 重复 BFS + DFS 直到 $t$ 不可达。
   - 复杂度：$O(V^2E)$，对单位容量图 $O(E\sqrt{V})$。
   - 对比：Edmonds–Karp 为 $O(VE^2)$；Ford–Fulkerson 在实数容量下可能不终止。
2. **最小费用流——SPFA/Bellman-Ford 增广**（费用可能为负时）或 **Dijkstra + 势能**（费用非负时）：
   a. 初始化零流，势 $\pi=0$；
   b. 用带势的 Dijkstra 在原残量网络求 $s$-$t$ 最短路（以 $c_{ij}+\pi_i-\pi_j$ 为权）；
   c. 沿最短路增广（增广量 = 路径上最小残量）；
   d. 更新势，重复直到无增广路或达到目标流量。
   - 复杂度：每次最短路 $O(E\log V)$，增广次数 $O(v^*)$，总计 $O(v^* E\log V)$。
3. **网络单纯形法**（大规模首选）：把网络流写成 LP，用专门的主元规则，实测比通用 LP 快 10—100 倍。
4. **最优性验证**：用最小割证明最大流最优；用势函数非负性验证费用流最优。
5. **2000B 的特殊性**：该题费用非线性的部分不能直接套标准算法——原文说"不能直接套用标准最小费用最大流的复杂度计算公式"〔原文〕，需要**分段线性化**或改进算法。

## 8. Python实现思路

- **NetworkX**：
  - 最大流：`nx.maximum_flow(G, s, t)`（默认 capacity 属性名 `'capacity'`）；
  - 最小费用流：`nx.max_flow_min_cost(G, s, t)`（**注意：这是"最小费用最大流"，先保证最大流再最小费用**）；若只要"指定流量的最小费用"，用 `nx.min_cost_flow` + `demand` 属性。
  - 最小割：`nx.minimum_cut(G, s, t)`。
- **OR-Tools**：`pywrapgraph.SimpleMaxFlow()` / `SimpleMinCostFlow()`，C++ 内核，**速度快几个数量级**，大规模问题首选。
- **PuLP + CBC**：把网络流写成 LP 直接解，**优点是能同时加额外的非网络约束**（如 2021C 的"一家供应商每周尽量由一家转运商运输"），NetworkX 做不到。
- **易错点1**：NetworkX 需要**有向图**；用无向图建模双向边时，两条反向边的容量会互相干扰，必须显式建两条 Arc 或拆分节点。
- **易错点2**：`max_flow_min_cost` 的 cost 属性名是 `'weight'` 不是 `'cost'`，写错会当 0 处理（得到任意解却"费用为 0"）。
- **易错点3**：浮点容量（如 6000.0 m³）会让某些实现精度出错，尽量化整（把单位从 m³ 换成 0.1 m³ 再取整）。
- **易错点4**：节点命名重复（供应商和转运商都叫 "1"）导致图被合并——**必须加前缀**。
- **易错点5**：忘了给虚拟源/汇加边，导致流为 0 或全部走单条边。

## 9. MATLAB实现思路

- **内置**：`maxflow(G, s, t)`（有向图 `digraph`），返回最大流值；`G.Edges` 里可读回每边流量。
- **最小费用流**：MATLAB **没有内置函数**。两条路：
  a. 用 `optimproblem`/`linprog` 直接建 LP（网络流的 LP 形式很紧凑，推荐）；
  b. 自己实现 Busacker–Gowen（用 `shortestpath` 反复增广）。
- **最小割**：`[mf, GF, CS, CT] = maxflow(...)`，`CS` 与 `CT` 就是割的两侧节点集。
- **易错点1**：`maxflow` 要求 `digraph`，用 `graph`（无向）会报错或语义不符。
- **易错点2**：`maxflow` 的容量是 `G.Edges.Weight`，必须显式设置。
- **易错点3**：自实现增广时忘记更新反向边（残量），得到错误结果且不报错。
- **易错点4**：用 `linprog` 建流问题时要写流量守恒等式约束，维度容易错位，建议写成矩阵后 `size` 断言。
- **易错点5**：负费用边用 `shortestpath`（Dijkstra 内核）会失败，需用 Bellman-Ford（MATLAB 的 `shortestpath` 支持 `'Method','positive'` 或自动检测负权，但仍不支持负环）。

## 10. 优点

1. **整数性自动成立**：整数容量 → 整数最优解，不需要 MILP，比通用整数规划快得多。
2. **有最优性证书**：最小割 = 最大流，可以给出**可验证的最优性证明**，这在国赛里很加分。
3. **可加业务约束**：写成 LP 后可自由添加额外约束（这是网络流相对纯图算法的优势）。
4. **模型直观**：画一张网络图，评审一眼就懂。
5. **求解器成熟**：Dinic、网络单纯形都是工业级实现，万级节点轻松处理。

## 11. 缺点

1. **只支持线性费用**：非线性费用（规模折扣、分段运价）需分段线性化，规模成倍增加。
2. **单商品限制**：多商品流（不同货物不能混装）是 NP-hard，需上 MILP。
3. **损耗/转化破坏守恒**：带损耗的运输不适合直接建标准流模型，需要技巧。
4. **建模门槛**：把业务问题正确翻译成网络结构需要经验，节点/边设计错误会导致结果完全错。
5. **路径信息需后处理**：算法给的是**边流量**，要还原成"哪辆车走哪条路"需要额外的流分解。

## 12. 适用条件

- **当**问题可自然表示为"带容量与单位费用的有向网络上的流量分配"时，用网络流。
- **当**费用与流量成正比（线性）时，用标准最小费用流；费用分段时先分段线性化。
- **当**要求"运输量最大"且容量有限时，用最大流 + 最小割分析瓶颈。
- **当**问题需要额外的非网络约束（如"每条供应商-转运商配对每周至多一条"）时，写成 LP/MILP 而不是用纯图算法。
- **与本三题相关的明确判断**：
  - **2026C**：**弱相关**。微网购电的"电量从外网流向微网、从储能流向负载"可以画成流网络，但因为**储能可以双向流动且有状态（电量）**，标准静态网络流表达不了时间维度。**建议仍用 LP/MILP**，网络流只在"多微网之间的电力互济"这类扩展场景下才有价值。 〔推理〕
  - **2026D**：**强相关（结构上）**。150 条用频计划的时频冲突，可理解为**"时间-频率二维资源"上的占用冲突**，是"区间冲突图"问题；问题3"在不增加时频资源的前提下最多还能安排多少 C 类装备"，形式上就是**在二维资源网格上求最大独立集/最大装箱**，可用流/匹配方法求界。**但注意：区间图上的最大独立集、最大团都是多项式可解的**（区间图是完美图），这比一般网络流更贴切。 〔原文 + 推理〕
  - **2026B**：**弱相关**。机器狗在圆域内移动，若把区域栅格化可用最短路/网络流，但**在线的搜索-清除问题**不是静态网络流能解决的。 〔推理〕

## 13. 不适用情况

- **当**费用非线性且无法分段线性化时（如费用正比于流量的平方），不要用标准最小费用流。
- **当**有多种货物且不能混装（多商品流）时，不要用单商品流模型，改 MILP。
- **当**网络结构本身是决策变量（要同时决定"修哪条路"）时，标准流算法不适用，应上**网络设计问题（NP-hard）**的 MILP。
- **当**流量必须取整数且容量很大（如 $10^6$）时，如果还要加额外约束，直接 LP/MILP 比逐次增广更快。
- **当**存在负费用环时，标准最短增广路算法会失败（需专门的消环算法）。
- **当**问题是"每辆车走哪条路"这种路径级决策时，光有边流量不够，需要额外分解（见《车辆路径问题VRP》）。

## 14. 常见错误

1. **正向反向边搞错**：把"双向可通行"建成了无向图，容量被错误共享。正确做法是建两条有向边（各自有容量），或在残量网络中区分"原边"与"残量反向边"。
2. **损耗处理错误**：直接把"供货量 × (1-损耗率)"当作边容量，会导致流量守恒被破坏，结果偏移。正确做法是把损耗折进费用或拆成"发货节点 + 收货节点"两条边。
3. **忘了拆点处理节点容量**：如果节点本身有通过能力上限（如中转站吞吐量），必须把节点拆成"入点 + 出点 + 一条容量受限的中间边"。
4. **虚拟源汇容量设错**：虚拟源到供应商的边容量应等于该供应商的**供应上限**而非无穷；设无穷会让求解器把全部需求压到一个供应商上。
5. **把"最小费用最大流"与"最小费用流"混用**：前者强制流量最大，后者可指定流量。若题目要求"至少满足需求"，应用后者（带 demand）。
6. **单位不一致**：费用按"元/吨公里"而边权只写了"元/吨"，忘记乘距离；或距离单位是 km 而题目是 m。
7. **负数/零容量边**：容量为 0 的边会让某些实现出错；应直接不建这条边。
8. **没验证可行性**：最大流值 < 总需求时，说明容量不足，此时应报告"缺口"而不是硬报一个方案。

## 15. 论文写法

**可套用句式**：

1. "以各供应点、转运商与企业仓库为节点，以实际可转运路径为有向边，边容量取转运商周运力 6000 m³，边费用取单位转运成本，建立最小费用最大流模型。"
2. "由最大流最小割定理可知，网络的最大流等于最小割容量；求解得到最小割为 {(S₂,T₁)}，割容量 48000 m³，即系统每周最大可转运量为 48000 m³，瓶颈在于第 2 号供应商至第 1 号转运商的通道。"
3. "由于容量均为整数，由整数流定理知该网络存在整数最优流，因此所求得的运输方案天然满足'整车/整批运输'的整数要求。"
4. "为处理题目给出的转运损耗，本文将每条边拆为'发货边'与'收货边'，并在其间以损耗率折算流量，从而在保持流量守恒的前提下刻画损耗。"

**应配的图表**：

- **网络结构图**（节点分层排列，边上标注 $(c_{ij}, u_{ij})$，即"费用,容量"，这是网络流论文的核心图）；
- **最优流方案图**（边宽或线粗表示流量大小）；
- **最小割示意图**（用虚线标出割集，直观展示瓶颈）；
- **流量—费用累积曲线**（横轴流量、纵轴累计费用，凹性/凸性能说明边际成本变化）；
- **方案汇总表**（每条边的流量 + 折算业务量）。

## 16. 可创新方向

1. **分段线性化非线性运费**（**2000B 的核心难点**）：把"非线性费用的网络流"用若干条平行边代替（每段一条边，容量为该段长度，费用为该段斜率），转成标准最小费用流。原文明确说该题需要"改进传统的最小费用最大流算法"〔原文〕，这是最好的参照。
2. **带损耗/转化的广义流（generalized flow）**：边有增益因子 $\gamma_{ij}$（流出 = 流入 × $\gamma$），是标准网络流的自然推广，可用 LP 直接解。
3. **多商品流 MILP**：不同原料/货物不能混装时，用多商品流建模并报告计算规模。
4. **鲁棒/随机网络流**（与《鲁棒优化与随机规划》联动）：容量或需求不确定时求"最坏情况下最大流"或"以某概率满足需求的流"。
5. **网络流 + 时间维度（时变流）**：2021C 的 24 周订购—转运是"动态网络流"，可用时间扩展网络（time-expanded network）建模，是本卡片最有价值的创新点之一。
6. **与 2026D 的结合点**：把"时间 × 频率"的二维资源离散成网格，用**最大流/最大匹配**求"在已有占用下最多还能插入多少个 C 类计划"，给出上界；再用冲突图独立集给出构造解，两者对比即得 gap。 〔推理〕
7. **与 2026B 的结合点**：若把圆域栅格化，可用最大流判断"用有限步数能否覆盖全部可能位置"，作为搜索完备性的理论支撑（偏理论，风险较高）。 〔推理〕

**与 2026 三题的接口**（本节小结）：
- **2026B**：弱。栅格化后可用流模型，但在线搜索-清除不是静态流问题。
- **2026C**：弱。储能的双向流动与时间状态使静态网络流失效；仅在"多微网互济"扩展中有价值。
- **2026D**：**中强（结构上）**。问题3 的"最多还能插入多少 C 类"可用最大流/最大匹配求上界；同时提醒：区间图上的最大独立集是多项式可解的，比一般流更贴切。
