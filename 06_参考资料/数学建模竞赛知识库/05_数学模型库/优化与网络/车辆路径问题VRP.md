# 车辆路径问题VRP

> **证据等级说明**：〔原文〕= 语料中直接读到的句子/标题；〔归纳〕= 从多篇语料共有的写法中归纳；〔推理〕= 无直接语料支撑、由模型性质推出的判断。

## 1. 模型用途

VRP：给定**一个（或多个）车场、若干客户点、一支车队**，在满足车辆容量（有时还有时间窗、最大里程、司机工时）的前提下，确定每辆车的行驶路线，使总成本最小。它是 TSP 的"带约束 + 多车"版本。

国赛里的对应问题：

- **矿区车辆调度**：2003B 露天矿生产的车辆安排——装车点（电铲）与卸车点（卸矿点）之间的车辆分配〔原文〕；
- **多组巡视分区**：1998B 灾情巡视（mTSP，可视作无容量约束的 VRP）〔原文〕；
- **订购与转运配送**：2021C 原材料从 402 家供应商到企业仓库、由 8 家转运商承运〔原文〕；
- **巡检排班路径**：2017D 巡检线路的排班，正文"使用**最短路模型**，找到了最短回路"〔原文〕；
- **景区/场馆游览路线**：2010B 世博会参观线路设计〔原文〕。

**一句话判断**：TSP 是"一个人走完全部点"，VRP 是"几个人分担走完全部点，每人有容量/时间限制"。

## 2. 题目特征

1. **题眼词**："车辆""车队""运输""配送""调度""装车""派出多少辆"。
   - 2003B 系列评述论文自述为"车辆安排"问题，并出现"多目标规划""整数线性规划""遗传算法"〔原文〕
   - 2021C 原句："每家转运商的运输能力为 **6000 立方米/周**"、"通常情况下，一家供应商每周供应的原材料尽量由一家转运商运输"〔原文〕
2. **有"容量/载重/车厢数/趟数"约束**：这是 VRP 区别于 TSP 的核心标志。
3. **有"多辆车/多个组/多趟"**：要决定派几辆、怎么分组。
4. **有"服务点 + 车场"结构**：从某处出发再回来，或从装点跑到卸点。
5. **可能有时间窗**："必须在 X 点前送达""错时上班"（2017D 原句："如果采用错时上班，重新讨论问题 1 和问题 2"〔原文〕）。

## 3. 数学原理

**来源**：Dantzig & Ramser（1959）首次提出；Clarke & Wright（1964）节约算法；Solomon（1987）时间窗扩展〔推理，属通用理论〕。

**成立前提**：

1. **客户需求已知且确定**（随机需求 → SVRP）。
2. **车辆同质或已知各车能力**（异构车队需额外建模）。
3. **容量约束可量化**（吨、m³、件数）。
4. **路网距离矩阵已知**（由最短路预先算出）。
5. **服务时间可忽略或已知**（有时间窗时不可忽略）。
6. **一车一回路**（允许多趟的"车辆多次出行 VRP"需额外建模）。

**复杂度**：VRP 是 NP-hard（TSP 的推广）。$n$ 个客户、$k$ 辆车的问题规模远大于 TSP，**实用规模上限约 100—1000 个客户**（启发式）。

**常用下界**：把 VRP 松弛为"每个客户的往返行程（radial bound）"：

$$\text{OPT}\ge \sum_{i}\frac{2d_{0i}q_i}{Q}+\cdots$$

更常用的实用下界是"总需求/单车容量"给出的**最少车辆数**：

$$k_{\min}=\Bigl\lceil \frac{\sum_i q_i}{Q}\Bigr\rceil$$

## 4. 基本公式

**经典 VRP（容量约束 CVRP）**：

$$\min\;\sum_{i\in V}\sum_{j\in V}c_{ij}x_{ij}$$

$$\text{s.t.}\quad \sum_{j\in V}x_{ij}=1,\;\forall i\in C\;(\text{每个客户被服务恰好一次})$$

$$\sum_{j\in V}x_{0j}=k,\qquad \sum_{i\in V}x_{i0}=k\;(\text{恰有 }k\text{ 辆车出车})$$

$$\sum_{i\in S}\sum_{j\in S}x_{ij}\le |S|-1,\;\forall S\subseteq C\;(\text{子回路消除})$$

$$\sum_{i\in C}q_i\sum_{j\in V}x_{ij}\le Q\;(\text{单车容量，需按车展开})$$

**带时间窗（VRPTW）**：

$$a_i\le t_i\le b_i,\qquad t_j\ge t_i+s_i+\tau_{ij}-M(1-x_{ij})$$

**最小车辆数下界**：

$$k_{\min}=\Bigl\lceil \frac{\sum_{i\in C}q_i}{Q}\Bigr\rceil$$

**Clarke–Wright 节约值**：

$$s_{ij}=c_{0i}+c_{0j}-c_{ij}$$

（把两条往返路线 $0\!\to\!i\!\to\!0$、$0\!\to\!j\!\to\!0$ 合并成 $0\!\to\!i\!\to\!j\!\to\!0$ 所节省的距离。）

**2003B 型"装点—卸点"配车公式**（铲车与卡车匹配）：

$$N_{\text{车}}=\Bigl\lceil \frac{T_{\text{周期}}}{T_{\text{装}}+T_{\text{卸}}+2T_{\text{运行}}}\Bigr\rceil\cdot(\text{同时作业的铲位数})$$

（**具体形式必须按题目给定的装车时间与运距推导，不能照抄**〔归纳〕）

## 5. 参数含义

| 符号 | 含义 | 例 |
|---|---|---|
| $C$ | 客户集合 | 402 家供应商、卸矿点 |
| $0$ | 车场/仓库 | 企业仓库、矿石破碎站 |
| $q_i$ | 客户需求 | 每周供货量 m³ |
| $Q$ | 车辆容量 | 转运商运力 6000 m³/周 |
| $c_{ij}$ | 距离/时间/成本 | 由最短路矩阵给出 |
| $k$ | 车辆数 | 需决策 |
| $[a_i,b_i]$ | 时间窗 | 巡检周期要求 |
| $s_i$ | 服务时长 | 装车/卸车时间 |

## 6. 建模步骤

1. **确定"客户"与"车场"**：谁被服务、谁提供服务。
2. **算距离矩阵**：路网最短距离（Floyd/Dijkstra）或欧氏距离。
3. **算车辆数下界**：$k_{\min}=\lceil\sum q_i/Q\rceil$，作为决策变量 $k$ 的起点。
4. **写约束**：访问一次、容量、时间窗、最大里程、司机工时。
5. **定目标**：总里程最小 / 总成本最小 / 车辆数最少 + 里程最小（常是多目标）。
6. **选算法**：
   - $n\le 20$ 且要求精确 → 分支定价/割平面（一般队伍做不出来）；
   - $20<n\le 200$ → OR-Tools 的引导局部搜索（**强烈推荐**）；
   - 自写 → 节约算法构造 + 2-opt/Or-opt 改进，或遗传算法。
7. **求解并校验**：逐车检查容量、时间窗是否满足。
8. **均衡性检查**：各车里程/载重是否均衡（题目常要求"工作量相对均衡"）。
9. **敏感性分析**：容量或需求变化对车辆数与总成本的影响。

## 7. 算法

1. **构造式——Clarke–Wright 节约算法**：
   a. 初始：每个客户一条往返路线 $0\!\to\!i\!\to\!0$；
   b. 计算所有客户对的节约值 $s_{ij}=c_{0i}+c_{0j}-c_{ij}$；
   c. 按 $s_{ij}$ 降序排列；
   d. 依次尝试合并路线：若 $i$、$j$ 分属不同路线、且都位于各自路线的端点、且合并后总需求 ≤ $Q$，则合并；
   e. 直到无法再合并。
   - 复杂度：$O(n^2\log n)$（排序主导）。质量：平均比最优差 5%—10%。
2. **改进式——2-opt / Or-opt / Relocate / Exchange**：
   a. 对每条路线内做 2-opt（$O(m^2)$）；
   b. 跨路线做 Relocate（移动一个客户到另一条路线，$O(n^2)$）与 Exchange（交换两个客户）；
   c. 反复直到无改善。
   - 复杂度：一轮 $O(n^2)$，通常迭代 $O(n)$ 轮。
3. **元启发式**：
   a. **引导局部搜索（GLS）**（OR-Tools 默认）：在局部最优后对频繁出现的边加惩罚，跳出局部最优；
   b. **模拟退火 / 禁忌搜索 / 大规模邻域搜索（LNS/ALNS）**：ALNS 是当前最强实用方法之一，随机选择 destroy/repair 算子；
   c. **遗传算法**：染色体为"客户排列 + 分割"，或直接多染色体编码。
4. **精确算法**（小规模）：
   a. 集合划分模型 + 列生成（branch-and-price）；
   b. 割平面（DFJ 割 + 容量割）。
5. **复杂度**：精确解最坏指数级；Clarke–Wright $O(n^2\log n)$；2-opt 一轮 $O(n^2)$；ALNS 视迭代次数而定。

## 8. Python实现思路

- **OR-Tools（首选，没有之一）**：
  - `RoutingIndexManager(num_nodes, num_vehicles, depot)`；
  - `routing.AddDimensionWithVehicleCapacity(...)` 加容量维；
  - `routing.AddDimension(...)` + `CumulVar.SetRange(...)` 加时间窗；
  - `search_parameters.local_search_metaheuristic = SEARCH_GUIDED_LOCAL_SEARCH`；
  - `search_parameters.time_limit.FromSeconds(60)`。
  - **它能直接给出可行的多车路线，省掉 90% 的实现工作量**。
- **自写节约算法**：numpy 存距离矩阵，`for` 循环实现合并逻辑，50 行以内。
- **VRPLIB / vrpy**：`vrpy.VehicleRoutingProblem` 支持 CVRP/VRPTW，内部用列生成，小规模可求精确。
- **易错点1**：车辆数不是决策变量而是超参数时，忘记给"空车"允许（OR-Tools 里要设 `SetAllowedVehiclesForIndex` 或允许车辆闲置），否则会报 infeasible。
- **易错点2**：容量维忘了设 `SetGlobalSpanCostCoefficient` 或 `start_cumul_to_zero=False`，导致载重计算从 0 开始但语义错误。
- **易错点3**：时间窗用绝对时间还是相对时间没统一，跨零点会出错。
- **易错点4**：距离矩阵含 `inf`（不可达）时要去掉对应边或加大数值，否则求解器报错。
- **易错点5**：目标只写"总里程最小"，结果一辆车跑完全部（等价于 TSP），忽略了题目"均衡"要求——需加最大路线长度的惩罚。
- **易错点6**：OR-Tools 默认使用 `PATH_CHEAPEST_ARC` 构造，质量一般，**务必换成引导局部搜索 + 给足时限**。

## 9. MATLAB实现思路

- **MATLAB 无内置 VRP 求解器**。三条路：
  a. 用 `optimproblem` + `intlinprog` 写 CVRP 的 MILP（$n$ 小才可行，需自己加子回路消除）；
  b. 自写节约算法 + 2-opt（约 100 行）；
  c. 用 `ga` 配合自定义编码 + 惩罚函数。
- **导航工具箱**：MATLAB 有 `nav`（Navigation Toolbox）但偏机器人路径规划，不含 VRP。
- **画图**：`plot` 逐条路线绘制，不同颜色区分车辆。
- **易错点1**：用 `intlinprog` 写 VRP 时**必须加子回路消除约束**，否则求解器会给出一堆互不相连的小回路。
- **易错点2**：子回路消除约束数量是 $2^n$ 级，只能对违反了的小集合动态加（不然约束数爆炸）。
- **易错点3**：用 `ga` 时惩罚系数设得过大导致搜索退化，过小导致大量不可行解。
- **易错点4**：节约算法合并时未检查"点是否在路线端点"，合并出非法路线。
- **易错点5**：未做车容量校验就输出结果，容易出现某车超载。

## 10. 优点

1. **贴合真实物流/调度场景**：题目一出现"车队、运力、配送"就是它。
2. **能表达多目标**：车辆数、总里程、最长路线、均衡性可组合。
3. **算法生态成熟**：OR-Tools 让 CVRP/VRPTW 变成"调库题"。
4. **下界易算**：$k_{\min}=\lceil\sum q/Q\rceil$ 与放射下界给出基本质量基准。
5. **结果高度可视化**：一张多色路线图 + 一张车辆装载表就讲清楚了。

## 11. 缺点

1. **NP-hard 且比 TSP 更难**：约束一多，求解时间指数增长。
2. **对建模细节极敏感**：容量单位、时间窗起止、服务时长，任一处错都会导致不可行或结果失真。
3. **多目标难兼顾**：总里程最小与车辆数最少、与均衡性天然冲突。
4. **精确解基本不可能**：$n>30$ 就得靠启发式，无最优性保证。
5. **随机/动态扩展更难**：需求实时到达的 DVRP 需要滚动重优化。

## 12. 适用条件

- **当**题目有"多个客户点 + 有限容量车辆 + 从车场出发返回"的结构时，用 VRP。
- **当**车辆数也是决策变量时，用"最小车辆数下界 + 逐步增加车辆数比较总成本"的标准循环。
- **当**有时间窗时，用 VRPTW；**当**有取货送货配对时，用 PDP（取送货问题）。
- **当**$n\le 100$ 时，OR-Tools 的引导局部搜索通常能在分钟级给出很好的解。
- **与本三题相关的明确判断**：
  - **2026B**：**强相关**。机器狗是"**一辆车**"（$k=1$），要去访问/清除多个已知或未知目标——**这是"单车 + 覆盖约束 + 在线信息"的 VRP/覆盖路径规划**。题面明确机器狗沿直线行进、速度 5 m/s〔原文〕，因此距离矩阵就是欧氏距离。**建议做法**：① 把"检测到目标"视为新增客户；② 用滚动 VRP/TSP 重优化；③ 用"覆盖半径 = 有效接收半径 1000—1500 m"的检测能力构造覆盖约束，而不是硬要求走到每个点。**这最后一点是本题最重要的建模洞察**。 〔原文 + 推理〕
  - **2026C**：**弱相关**。微网购电本身不是配送问题；但若扩展为"多微网之间的电力互济"或"储能设备的移动式调度"，则可套 VRP 框架——**属于外延而非主线**。 〔推理〕
  - **2026D**：**不适用**。D 题无路径/配送结构。 〔推理〕

## 13. 不适用情况

- **当**只有一辆车且无容量限制时，直接用 TSP，不要套 VRP 的复杂框架。
- **当**客户需求随机、需要实时响应时，标准 CVRP 不适用，应用 DVRP 或滚动优化。
- **当**车辆数是固定的且题目只问"哪辆车服务哪些客户"时，这更接近**指派问题 + 各自 TSP**，不需要完整的 VRP 建模。
- **当**没有车场（开放式路线）时，用开放式 VRP（OVRP），别硬加"返回车场"约束。
- **当**容量约束实际上不起作用（如运力远大于需求）时，简化成 mTSP 更清晰。
- **当**$n>500$ 且要求近实时时，不要用元启发式在线求解，应预计算分区策略。

## 14. 常见错误

1. **忘了子回路消除**：用 MILP 写 VRP 时只写"每个客户入度=出度=1"，求解器会给出 5 个互不相连的小回路，且目标值看起来"更优"。**必须加 DFJ 割或 MTZ 约束**。
2. **容量单位不统一**：需求用 m³、容量用吨，直接相加。**必须先统一量纲**（2021C 的需求单位是 m³，运力也是 m³/周，但损耗率是百分比，混算极易出错）。
3. **车辆数下界算错**：$ lceil\sum q/Q\rceil$ 只是下界，实际因地理分散常需要更多车；直接把它当答案会不可行。
4. **时间窗建模方向搞反**：$t_j\ge t_i+s_i+\tau_{ij}$ 是"后到"，写成 $\le$ 就成了"必须先到远的"。**加 M 线性化时符号尤其容易错**。
5. **忽略均衡性**：2003B、2017D 这类题常要求"工作量相对均衡"，只最小化总里程会得到极端分配。
6. **服务时长漏算**：装车/卸车时间不计入时间窗推算，导致实际不可行。
7. **距离矩阵用了欧氏距离却存在绕行**：矿区、山地、单行道必须用路网最短路。
8. **启发式时限设置过长**：比赛时设 `time_limit=3600` 结果卡死；应设 60—300 秒并用 `best_bound` 监控。

## 15. 论文写法

**可套用句式**：

1. "以各装车点（电铲）与卸车点为节点、以实际运输路径长度为边权，构建距离矩阵；设共有 $k$ 辆卡车，每辆车容量为 $Q$，建立带容量约束的车辆路径问题（CVRP）模型。"
2. "由总需求 $\sum q_i=48600$ m³ 与单车容量 $Q=6000$ m³ 得所需车辆数下界 $k_{\min}=\lceil 8.1\rceil=9$ 辆；本文对 $k=9,10,\dots,13$ 分别求解并比较总成本，得最优车辆数为 11 辆。"
3. "由于 CVRP 属于 NP-hard 问题，本文采用 Clarke–Wright 节约算法构造初始解，再用 2-opt 与 Or-opt 进行邻域改进，总耗时 42 s，最终总运输里程为 863.2 km。"
4. "为保证各组工作量均衡，本文在目标函数中加入最大单组里程的惩罚项 $\lambda\max_k L_k$，使各组里程极差从 47.3 km 降至 6.8 km，而总里程仅增加 1.2%。"

**应配的图表**：

- **多车路线图**（每辆车一种颜色，标注车场位置）；
- **车辆装载与里程汇总表**（每辆车的客户序列、载重、里程、时间窗满足情况）；
- **车辆数—总成本曲线**（横轴车辆数 $k$、纵轴总成本，标出最优点，展示"车辆数边际效益"）；
- **算法对比柱状图**（节约算法 / 2-opt / GLS / ALNS 的解质量与耗时）；
- **收敛曲线**（迭代次数 vs 目标值）。

## 16. 可创新方向

1. **覆盖型 VRP（Covering VRP）**（**2026B 强相关**）：不要求车辆到达每个客户，只要求"每个客户被某条路线的某个位置的服务半径覆盖"。**这正是 2026B 的真实结构**——机器狗的有效接收半径 1000—1500 m〔原文〕意味着不必走到干扰源跟前就能检测。把这个"覆盖"而非"访问"的结构写清楚，是本题最好的建模点。 〔原文 + 推理〕
2. **在线/动态 VRP（DVRP）**：目标逐个被发现，每步滚动重优化。2026B 可用"每发现一个目标就重排剩余路线"的策略，并报告相对离线最优的代价。 〔推理〕
3. **随机 VRP（SVRP）**：需求或行驶时间随机时求期望最优，与《鲁棒优化与随机规划》联动（2021C 的"供应商不能保证严格按订货量供货"〔原文〕就是随机需求）。
4. **多目标 VRP + Pareto**：车辆数、总里程、均衡性、碳排放同时优化，用 NSGA-II 求前沿。
5. **VRP + 网络流混合**：2021C 的"供应商 → 转运商 → 仓库"是**双层运输网络**，可写成"指派（供应商到转运商）+ 车辆路径（转运商到仓库）"的混合模型，比单纯的 VRP 更有层次。 〔推理〕
6. **时变路网 VRP**：2024E 交通流量管控的通行时间随时段变化〔原文，题型判定含通路优化〕，可做时变 VRP。
7. **与 2021D 的接口**：连铸切割的"在线调整"思想（"在出现新的报废段后，给出新一段钢坯的切割方案和当前段钢坯切割的调整方案，或声明不作调整"〔原文〕）与 DVRP 的滚动重优化在方法论上完全一致，可互相借鉴。

**与 2026 三题的接口**（本节小结）：
- **2026B**：**强**。机器狗是"$k=1$ 的车队"，但核心是**覆盖型 VRP**——有效接收半径 1000—1500 m 意味着"检测覆盖"而非"到点访问"；目标逐个发现时转 DVRP 滚动重优化。
- **2026C**：弱。仅当扩展为"多微网电力互济/移动储能调度"时才相关，属外延。
- **2026D**：不适用。
