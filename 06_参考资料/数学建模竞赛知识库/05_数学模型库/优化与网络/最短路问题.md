# 最短路问题

> **证据等级说明**：〔原文〕= 语料中直接读到的句子/标题；〔归纳〕= 从多篇语料共有的写法中归纳；〔推理〕= 无直接语料支撑、由模型性质推出的判断。

## 1. 模型用途

给定一张赋权图，求两点之间（或所有点对之间）总权重最小的路径。在国赛里它几乎**从不单独出现**，而是作为**上层模型的计算内核**：

- **网络可达性/便捷度评价**：2016B 小区开放对周边道路通行的影响，用最短路算"可达度"〔原文〕；
- **公交/地铁换乘方案**：2007B 系列论文大量使用 Dijkstra 与 Floyd〔原文〕；
- **应急调度与封锁**：2011B 交巡警平台的警力封锁路径〔原文〕；
- **巡检/巡检回路**：2017D 巡检线路排班，原文"使用最短路模型，找到了最短回路"〔原文〕；
- **逃生路径**：2025D 矿井突水逃生〔真题，无优秀论文〕；
- **多目标寻优的骨架**：2007B《关于多目标道路寻优问题的研究》〔原文标题〕。

**一句话判断**：只要题目里有"从 A 到 B 怎么走最好"，先问"权重是什么、是单目标还是多目标"。

## 2. 题目特征

1. **题眼词**："路径""路线""到达""距离""通行时间""换乘""最短""最快""最省"。
   - 2017D 原句："现需要建立模型来安排巡检人数和巡检路线，使得所有点都能按要求完成巡检"〔原文，N02 编目〕
   - 2011B 原句："请为各交巡警服务平台分配管辖范围，使其在所管辖的范围内出现突发事件时，尽量能在 3 分钟内有交巡警（警车的时速为 60km/h）到达事发地"〔原文〕
2. **给了网络结构**：节点 + 边 + 权重（或给了可算权重的坐标与速度）。
3. **字数/换乘次数也要最优**：多权重 → 多目标最短路。
   - 2007B 原句："《基于最小换乘次数的公交路线选择研究》"〔原文（文件标题）〕
4. **需要"到所有点的最短距离矩阵"**：Floyd 型（2011B 用 Floyd〔原文，检索命中〕）。

## 3. 数学原理

**来源**：Dijkstra（1959）非负权最短路；Bellman（1958）、Ford（1956）处理负权；Floyd（1962）、Warshall 求全源最短路〔推理，属通用理论〕。

**成立前提**：

1. **非负权**（Dijkstra 的硬要求）：若存在负权边，Dijkstra 的贪心正确性被破坏，必须换 Bellman-Ford/SPFA。
2. **无负权环**：有负环则最短路无下界（可无限绕）。
3. **权重可加**：$w(P)=\sum_{e\in P}w(e)$。若"权重"是不可加的（如"最大坡度""最窄路段宽度"），那是**瓶颈路问题**，需要用最大最小路算法（变形的 Dijkstra，用 $\max$ 代替 $+$，用 $\min$ 代替取小）。
4. **静态网络**：边权不随时间变化。**时变路网**（早晚高峰通行时间不同）需要时间依赖最短路（TDSP）。
5. **确定性**：权重已知。若通行时间随机，则是随机最短路（分布型最短路）。

**核心性质**：

- **最优子结构**：最短路的后缀仍是最短路——这正是 Dijkstra 与 DP 的共同基础。
- **Dijkstra 的贪心正确性依赖非负权**：因为一旦确定某点最短，后续不可能通过更长的路把它缩短。有负边时这个论证失效。

## 4. 基本公式

**最短路问题**：

$$\min_{P\in\mathcal{P}_{st}}\; w(P)=\sum_{e\in P}w(e)$$

**Bellman 方程 / 松弛操作**：

$$d(v)\leftarrow\min\bigl\{d(v),\; d(u)+w(u,v)\bigr\}\qquad \forall (u,v)\in E$$

**Floyd 递推**（全源）：

$$D^{(k)}_{ij}=\min\bigl\{D^{(k-1)}_{ij},\; D^{(k-1)}_{ik}+D^{(k-1)}_{kj}\bigr\}$$

初始 $D^{(0)}_{ij}=w(i,j)$（无边取 $\infty$，$D_{ii}=0$）。

**时变网络**（边权依赖出发时刻）：

$$d(v,t)=\min_{u}\bigl\{d(u,t')+w_{uv}(t')\;\big|\;t'\ge t\bigr\}$$

**多目标最短路**（2007B 型）：路径 $P$ 的向量权重 $\mathbf{w}(P)=(w_1(P),w_2(P))$，求 Pareto 最优路径集（见《多目标优化与Pareto前沿》）。

**通行时间到权重的换算**（2011B 型）：

$$w_{ij}=\frac{\text{欧氏或路网距离}}{v},\qquad v=60\ \text{km/h}\Rightarrow w_{ij}=\frac{d_{ij}}{16.67}\ \text{s}$$

## 5. 参数含义

| 符号 | 含义 | 例 |
|---|---|---|
| $G=(V,E)$ | 路网 | 交通节点与路段 |
| $w(u,v)$ | 边权 | 距离 / 时间 / 费用 / 换乘惩罚 |
| $d(v)$ | 源点到 $v$ 的最短距离 | km 或 min |
| $\pi(v)$ | 前驱节点（用于回溯路径） | 重建路径 |
| $D$ | 全源最短距离矩阵 | Floyd 的输出 |
| $t$ | 出发时刻（时变网络） | 早晚高峰 |

## 6. 建模步骤

1. **建图**：节点 = 路口/站点/平台/巷道端点；边 = 路段/线路。
2. **定权重**：明确权重物理含义（距离、时间、费用、换乘惩罚），**并写进符号说明表**。
3. **判断有向/无向**：单行道、公交线路有向；一般道路无向（建两条有向边）。
4. **检查非负**：若加了"换乘惩罚"等负奖励项，要么整体加常数变正，要么改用 Bellman-Ford。
5. **选择算法**：
   - 单源单汇/单源全源、非负权 → **Dijkstra**（堆优化）；
   - 有负权 → **Bellman-Ford / SPFA**；
   - 全源、节点数 ≤ 500 → **Floyd**；
   - 图很稀疏 + 单源 → Dijkstra + 邻接表。
6. **处理多目标**：先算各单目标最短路，再找 Pareto 路径集；或做加权。
7. **回溯路径**：存前驱数组，从汇点倒推。
8. **敏感性/场景分析**：权重变化（如道路施工使某边失效）下重算，比较路径变化。

## 7. 算法

1. **Dijkstra（堆优化）**：
   a. 初始化 $d(s)=0$，其余 $\infty$；$S=\varnothing$；
   b. 用最小堆取 $d$ 最小的未确定节点 $u$，加入 $S$；
   c. 对 $u$ 的每条出边松弛：若 $d(u)+w(u,v)<d(v)$ 则更新 $d(v)$ 与前驱，入堆；
   d. 重复直到堆空或 $t$ 被确定。
   - 复杂度：$O((V+E)\log V)$（二叉堆）/ $O(E+V\log V)$（斐波那契堆）。
2. **Bellman-Ford**：
   a. 初始化同 Dijkstra；
   b. 对所有边做 $V-1$ 轮松弛；
   c. 第 $V$ 轮若仍能松弛，说明存在负环，报告并终止。
   - 复杂度：$O(VE)$。
3. **Floyd–Warshall**：
   a. 初始化距离矩阵 $D$ 与路径矩阵 $P$；
   b. 三重循环 $k,i,j$，按递推式更新；
   c. 若 $D_{ii}<0$ 则存在负环。
   - 复杂度：$O(V^3)$，空间 $O(V^2)$。
4. **A*（有启发式时）**：$f(n)=g(n)+h(n)$，$h$ 需满足可采纳性（不高估），适合单次查询、图很大。
5. **K 短路（Yen 算法）**：求前 $K$ 条最短路径，用于"备选路线"分析。复杂度 $O(KV(E+V\log V))$。
6. **多目标最短路**：标签设定法（label-setting），每个节点维护一组非支配标签，最坏指数级。

## 8. Python实现思路

- **NetworkX**：`nx.dijkstra_path(G, s, t, weight='w')`、`nx.floyd_warshall_numpy(G, weight='w')`、`nx.bellman_ford_path(...)`、`nx.astar_path(...)`、`nx.all_pairs_dijkstra_path_length(...)`（一次算全源，比循环调用快）。
- **SciPy**：`scipy.sparse.csgraph.dijkstra / floyd_warshall / shortest_path`，输入是**稀疏邻接矩阵**，C 实现，**大规模首选**。
- **有向图注意**：`nx.Graph` 与 `nx.DiGraph` 行为不同，单行道必须用 `DiGraph`。
- **易错点1**：NetworkX 默认权重参数名是 `'weight'`，如果你把权重存在 `'length'` 属性却忘了传 `weight='length'`，它会**silently 用 1 当权重**，得到按边数最短的路径。
- **易错点2**：稀疏矩阵里"无边"必须用 0 表示（配合 `csgraph_from_dense(null_value=np.inf)`），用 `inf` 直接建稠密矩阵会内存爆炸。
- **易错点3**：Dijkstra 遇到负权会给出错误结果**且不报错**，务必先 `assert (weights >= 0).all()`。
- **易错点4**：节点 ID 若是字符串且含中文，某些版本会出错；统一转成整数 ID 更稳。
- **易错点5**：多目标问题用加权后单目标求解，只会得到一条路径，无法给出 Pareto 路径集。

## 9. MATLAB实现思路

- **首选**：`shortestpath(G, s, t, 'Method', 'positive'|'unweighted'|'mixed')` 返回路径节点序列；`distances(G)` 一次算全源距离矩阵；`shortestpathtree(G, s)` 得到最短路树。
- **`graph` vs `digraph`**：单行道用 `digraph`。
- **易错点1**：`shortestpath` 默认用边的 `Weight` 属性；若未设置，所有边权为 1。
- **易错点2**：`'Method','mixed'` 才支持负权（内部用 Bellman-Ford），用 `'positive'` 遇到负权会报错或给错解。
- **易错点3**：`distances` 在稠密图上内存 $O(V^2)$，$V>10^4$ 会爆内存。
- **易错点4**：`graph` 构造时重复边的处理规则是"取最后一条"或"最小值"（取决于写法），容易与预期不符——建图后应 `G.Edges` 检查。
- **易错点5**：`shortestpath` 返回的是节点序列，若还需要经过的边编号需用 `findedge` 二次查询。

## 10. 优点

1. **快**：Dijkstra 是 $O(E\log V)$，百万节点可实用。
2. **结论明确、易解释**：给出一条具体路线，论文里可以画出来。
3. **是大量模型的内核**：Floyd 矩阵是选址-覆盖模型的距离输入、是调度模型的通行时间输入。
4. **扩展性极好**：多目标、时变、K 短路、随机最短路都有成熟算法。
5. **有界可验证**：可以用对偶（势函数）验证最优性。

## 11. 缺点

1. **只管一条路径**：不考虑"多车同时走会不会拥堵"（那是交通流分配/UE 模型）。
2. **静态**：现实中通行时间随时段变化，静态最短路会高估早晚高峰的通行能力。
3. **单目标本质**：真实出行者同时看时间、费用、舒适度、换乘次数。
4. **假定边权准确**：实际路网数据有缺失、有误差，最短路对权重误差敏感（尤其接近平局的路径）。
5. **不支持路径级约束**：如"这条路不能走货车""必须经过某点"需要额外技巧（必经点可拆段求解）。

## 12. 适用条件

- **当**网络结构已知、边权非负且静态、目标是单一时，用 Dijkstra 或 Floyd。
- **当**需要全源距离矩阵（后续要做覆盖/选址/聚类）且节点数 ≤ 500 时，用 Floyd；更大时用"每个源跑一次 Dijkstra"。
- **当**存在负权（如"补贴""收益"作为权重）时，用 Bellman-Ford；有负环时必须先报告。
- **当**有权重是"不可加"的（最大坡度、最小宽度）时，用瓶颈路算法（改 Dijkstra 的松弛为 $\max/\min$）。
- **与本三题相关的明确判断**：
  - **2026B**：**强相关，是路径规划的内核**。机器狗以 5 m/s 直线行进〔原文〕，在圆域内访问多个检测点/清除点，本质是**在几何空间中做路径规划**。若把区域栅格化或只用"点—点直线"（因为无障碍物，欧氏距离即最短路），则最短路退化为**欧氏距离**——**这是本题的关键简化：题面没有障碍物，所以"最短路 = 直线"**。真正的难点变成"访问顺序"（TSP）而不是"怎么走"（最短路）。**论文里要明确写清这个简化及其依据**。 〔原文 + 推理〕
  - **2026C**：**不适用**。C 题没有网络结构。 〔推理〕
  - **2026D**：**不适用**（但"区间冲突图"是图论，不是最短路）。

## 13. 不适用情况

- **当**边权随时间显著变化且题目给了时序数据时，不要用静态最短路，应用时变最短路或分时段建模。
- **当**要同时决定多条路径的分配（多车、多用户）时，不要用最短路，应用**交通流分配（用户均衡/系统最优）**或 VRP。
- **当**问题是"必须经过所有点"时，最短路只是内层，外层是 TSP（见《旅行商问题TSP》）。
- **当**权重为负且图中有负环时，最短路无定义，不要硬算。
- **当**节点数极大（$10^6$ 以上）且需要实时查询时，不要每次跑 Dijkstra，应做**预处理**（Contraction Hierarchies、ALT 算法）。
- **当**路径需要满足"总长度不超过 L 且收益最大"这类资源约束时，这是**资源约束最短路（RCSP）**，NP-hard，需 DP 或标签法。

## 14. 常见错误

1. **权重属性名不匹配**：NetworkX 中忘传 `weight='xxx'`，导致按边数而非按距离求最短路。**最隐蔽的错误之一**，因为结果看起来完全合理。
2. **有向/无向搞反**：把单行道当双向，得到现实中不存在的路线。
3. **单位不统一**：距离用米、速度用 km/h，时间权重算错 1000 倍。
4. **负权未检查**：Dijkstra 遇到负权会给出错误的"最短路"且不报错，必须先断言。
5. **忽略换乘惩罚**：公交题中"换乘次数"必须显式建成权重（如每次换乘 +10 分钟），否则算法会给出换乘 5 次的"最短"路线。
6. **Floyd 内存溢出**：$V=10^4$ 时 $D$ 是 $10^8$ 个浮点（800 MB），必须先评估内存。
7. **路径回溯遗漏**：只算了距离没存前驱，最后无法给出路线。
8. **把最短路当路径规划全部**：在 VRP/TSP 场景里只求最短路会忽略"车辆容量、时间窗、多车"的约束。

## 15. 论文写法

**可套用句式**：

1. "以路口为节点、路段为边，以路段通行时间 $w_{ij}=d_{ij}/v$（$v=60$ km/h）为边权，构建有向赋权图 $G=(V,E)$；由于所有边权非负，本文采用堆优化的 Dijkstra 算法求单源最短路。"
2. "为获得全部服务平台到全部路口的通行时间矩阵，本文采用 Floyd–Warshall 算法，时间复杂度 $O(|V|^3)=O(582^3)$，实测耗时 0.8 s，满足实时调度要求。"
3. "在求得最短路矩阵的基础上，将'3 分钟到达'的约束转化为 $d_{ij}\le 3$ min 的覆盖关系，进而建立集合覆盖模型（见第 X 节）。"
4. "敏感性分析表明，当某主路段因施工而失效（边权置为 $\infty$）时，受影响路口的最短到达时间平均上升 23%，其中 7 个路口超出 3 分钟阈值，需重新划分管辖范围。"

**应配的图表**：

- **路网图 + 最短路高亮**（必须画，且最好用真实地理布局）；
- **最短距离矩阵热力图**（大矩阵用热力图展示，比表格清晰）；
- **算法耗时随节点数增长曲线**（证明算法可扩展）；
- **多目标最短路的 Pareto 路径集对比图**（展示"快 5 分钟但多换乘 2 次"）；
- **路径方案对比表**（时间、距离、换乘次数、费用并列）。

## 16. 可创新方向

1. **多目标最短路 + Pareto 路径集**（**2007B 的核心**）：同时优化时间、费用、换乘次数，用标签设定法或加权扫描给出一族非支配路径，比单条"最优路线"信息量大得多。 〔推理，与 2007B 强相关〕
2. **时变/随机最短路**：用时间依赖网络或通行时间分布，给出"95% 置信水平下 30 分钟内可达"的路径，比"期望最短"更贴近出行决策。
3. **K 短路 + 鲁棒性分析**：给出前 5 条最短路径并分析"某条边失效时的影响"，是很实用的工程结论。
4. **最短路 + 覆盖模型的两级框架**（**2011B 的范式**）：先用 Floyd 得通行时间矩阵 → 再建集合覆盖/选址模型。这个两级结构可以迁移到几乎所有"服务设施布局"题目。
5. **A* + 启发式设计**：在大规模路网上设计可采纳的启发函数（如欧氏距离/最大速度），报告加速比。
6. **与 2026B 的结合点**：由于题面无障碍物，**"最短路 = 欧氏直线"这一结论本身就是可写进论文的建模洞察**；真正的创新在于**把最短路作为 TSP/在线搜索的内层**，并分析"直线飞行 vs 栅格化路径"对总时间的影响。 〔推理〕
7. **与 2025D 的结合点**：矿井突水逃生路径是"**边权随时间变化**"（水位上升，逆水/顺水速度不同、超过 0.3 m 不建议通行）〔原文〕——这是**时变最短路 + 通行能力动态恶化**的绝佳场景，可用时间扩展网络建模。 〔原文 + 推理〕

**与 2026 三题的接口**（本节小结）：
- **2026B**：**强，但有一个可写进论文的关键简化**——题面无障碍物，故"最短路 = 欧氏直线"，真正的难点转移到访问顺序（TSP）。把这一点讲清楚本身就是建模洞察。
- **2026C**：不适用。
- **2026D**：不适用（但冲突图是图论，只是与最短路无关）。
