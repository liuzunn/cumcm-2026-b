## 1. 算法解决什么问题

**指派问题（Assignment Problem）与二分图最优匹配**：有 $n$ 个"任务"和 $n$ 个"执行者"，每个执行者完成每个任务的代价为 $c_{ij}$，求**一一对应**的分配方案使总代价最小（或总收益最大）。

**数学模型**：
$$\min\ \sum_{i=1}^{n}\sum_{j=1}^{n}c_{ij}x_{ij}\quad \text{s.t.}\quad \sum_{j}x_{ij}=1\ \forall i,\quad \sum_{i}x_{ij}=1\ \forall j,\quad x_{ij}\in\{0,1\}$$

**关键性质**：这是**运输问题的一个特例**，其约束矩阵是**全幺模的（totally unimodular）**，因此**线性规划的松弛解自动是整数解**——也就是说，**指派问题可以用 LP 求解器直接求解而无需分支定界**，而且一定有整数最优解。这是匈牙利算法（Kuhn–Munkres 算法）在多项式时间内精确求解的结构基础。

**匈牙利算法（Kuhn–Munkres, KM）**：基于"**可行势函数 / 对偶变量**"的思想——对每一行和每一列维护一个标号（势），通过不断寻找**增广路**来扩大匹配，直到找到完美匹配。时间复杂度 **$O(n^3)$**（改进版可到 $O(n^3/\log n)$）。

**国赛定位**〔归纳〕：指派类题目在国赛中出现频繁（**交巡警平台与路口的封堵指派、任务分配、人员排班、设备匹配**），但**语料中检索不到"匈牙利算法"这一名称**——优秀论文普遍直接把它写成 **0-1 规划 + LINGO/求解器**（见第 11 节）。**这是本卡片最重要的一条事实**。

## 2. 输入与输出

**输入**
- **代价矩阵 $C\in\mathbb R^{n\times n}$**（或收益矩阵，取负后转代价）；
- 是否方阵：若 $n_{\text{任务}}\ne n_{\text{执行者}}$，需**补虚拟行/列**（代价取 0 或一个大数 $M$，取决于物理含义）；
- 是否允许"无法执行"：用**大 M**（如 $10^6$）表示禁止指派；
- 是否需要 $k$-指派（每个执行者可接多个任务）：需**复制列**（把任务拆成 $k$ 份）。

**输出**
- **最优指派方案**：$\{(i,\sigma(i))\}$ 的排列 $\sigma$；
- 最小总代价 $z^*$；
- （对偶）行势 $u_i$、列势 $v_j$，满足 $u_i+v_j\le c_{ij}$，且对指派边取等号——**这是最优性证明的证书**。

**国赛常见转换**（把非标准问题化成标准指派）：
1. **最大化 → 最小化**：$c'_{ij}=-c_{ij}$，或 $c'_{ij}=\max_{kl}c_{kl}-c_{ij}$。
2. **非方阵**：补零行/列（等价于"允许某些任务不被执行"）。
3. **"最少平台封锁最多路口"**：路口数 > 平台数，需**复制平台行**（每个平台可封锁多个路口）或补虚拟列。
4. **禁止某些指派**：置大 $M$。
5. **带最小/最大封锁时间**：多目标 → 转化为"最小化最大时间"的**瓶颈指派问题（bottleneck assignment）**，可用阈值二分 + 可行性判定。

## 3. 算法步骤（伪代码级）

以 **$O(n^3)$ 的 Kuhn–Munkres（势函数 + 增广路）** 版本为例：

1. **初始化**：$u_i\leftarrow\min_j c_{ij}$（行势），$v_j\leftarrow0$（列势）；匹配 $\text{match}_j\leftarrow0$（每列尚未匹配）。
2. **对每一行 $i=1\dots n$**（逐个为行 $i$ 寻找匹配）：
   1. 初始化标号：$\text{way}\leftarrow\mathbf 0$；$\text{minv}_j\leftarrow+\infty$ 对所有 $j$；$\text{used}_j\leftarrow\text{false}$。
   2. $j_0\leftarrow0$；$\text{match}_0\leftarrow i$。
   3. **循环**（寻找增广路）：
      1. $\text{used}_{j_0}\leftarrow\text{true}$；$i_0\leftarrow\text{match}_{j_0}$；$\delta\leftarrow+\infty$；$j_1\leftarrow0$。
      2. 对每个 $j=1\dots n$ 且 $\text{used}_j=\text{false}$：
         1. $\text{cur}=c_{i_0 j}-u_{i_0}-v_j$。
         2. 若 $\text{cur}<\text{minv}_j$：$\text{minv}_j\leftarrow\text{cur}$；$\text{way}_j\leftarrow j_0$。
         3. 若 $\text{minv}_j<\delta$：$\delta\leftarrow\text{minv}_j$；$j_1\leftarrow j$。
      3. **更新势**：对所有 $j$：
         - 若 $\text{used}_j$：$u_{\text{match}_j}\leftarrow u_{\text{match}_j}+\delta$；$v_j\leftarrow v_j-\delta$；
         - 否则：$\text{minv}_j\leftarrow\text{minv}_j-\delta$。
      4. $j_0\leftarrow j_1$。
      5. **若 $\text{match}_{j_0}=0$**（到达未匹配列，找到增广路）：跳出内循环。
   4. **沿增广路回溯更新匹配**：$j\leftarrow j_0$；循环：$j'\leftarrow\text{way}_j$；$\text{match}_j\leftarrow\text{match}_{j'}$；$j\leftarrow j'$；直到 $j=0$。
3. **输出**匹配 $\text{match}$ 与总代价 $z^*=\sum_i c_{i,\sigma(i)}$。
4. **验证最优性**：检查 $u_i+v_j\le c_{ij}$ 对所有 $(i,j)$ 成立，且对匹配边取等号——**满足即证明最优**。

### 简化替代方案（国赛更实用）

**直接建 0-1 规划交给求解器**（语料中国赛论文的实际做法）：
1. 定义 0-1 变量 $x_{ij}$；
2. 目标 $\min\sum\sum c_{ij}x_{ij}$；
3. 约束 $\sum_j x_{ij}=1$（每行一个）、$\sum_i x_{ij}=1$（每列一个）、$x_{ij}\in\{0,1\}$；
4. 交给 LINGO / `scipy.optimize.linear_sum_assignment` / `intlinprog`。
5. **因为约束矩阵全幺模，可以直接解 LP 松弛，得到的就是整数解**——这一步可以在论文中作为"为什么不需要分支定界"的论证。

## 4. 复杂度与收敛性

| 方法 | 时间复杂度 | 空间复杂度 | 最优性 |
|---|---|---|---|
| **匈牙利算法（KM，$O(n^3)$ 版）** | $O(n^3)$ | $O(n^2)$ | **全局最优，精确算法** |
| 匈牙利算法（$O(n^4)$ 朴素版） | $O(n^4)$ | $O(n^2)$ | 全局最优 |
| **`scipy.optimize.linear_sum_assignment`（Jonker-Volgenant）** | 实际远快于 $O(n^3)$；$n=10^4$ 约数秒 | $O(n^2)$ | 全局最优 |
| 建 0-1 规划 + 分支定界 | 最坏 $O(2^{n^2})$，但**因全幺模性 LP 松弛即整数**，求解器通常一次 LP 就得到整数解 | $O(n^2)$ | 全局最优 |
| 暴力枚举 | $O(n!)$ | $O(n)$ | 全局最优，$n\le10$ 可用 |

**必须写进论文的结论**：
1. **匈牙利算法是精确算法，给出的是全局最优指派**——这是它相对所有启发式（GA/SA/贪心）的决定性优势，论文中可以写"最优"。
2. **指派问题的约束矩阵全幺模**，因此**其 LP 松弛的极点都是整数点**，LP 最优解自动是 0-1 解。**这意味着用 LP 求解器（LINGO 的 LP 模式、`linprog`）就能得到精确最优，且速度极快**。这是一条极有价值的论文论证。
3. **复杂度 $O(n^3)$**：$n=100$ 时约 $10^6$ 次操作（毫秒级）；$n=1000$ 时约 $10^9$（数秒到数十秒）。
4. **非方阵必须补齐**：补零会让"未指派"的代价为 0；补大 $M$ 会让它被强制指派。**补什么取决于业务含义**，这是最容易出错的地方。
5. **多目标（如"最小化最长封锁时间"）不能直接套标准匈牙利算法**：那是**瓶颈指派问题**，需"二分阈值 + 可行性判定"或"目标加权 + 字典序"处理。

## 5. 参数与调参要点

匈牙利算法本身**几乎没有参数**（这是它的重要优点）。需要决策的是**建模参数**：

| 参数/决策 | 推荐做法 | 依据 |
|---|---|---|
| **代价矩阵 $c_{ij}$ 的构造** | 必须写清每个元素的物理含义与单位（时间/距离/成本/满意度）；多指标时用加权或先归一化再加权 | 〔推理〕通用经验 |
| **最大化 → 最小化** | $c'_{ij}=\max_{kl}c_{kl}-c_{ij}$（保持非负）或直接 $c'=-c$（若允许负值，用 `linear_sum_assignment` 可处理） | 〔推理〕通用经验 |
| **非方阵补齐** | 行少于列 → 补零行（等价于允许某些列不被指派）；**若必须全部指派**，补的行/列代价取大 $M$ 并检查结果中是否出现 $M$ | 〔推理〕通用经验 |
| **禁止指派** | 用大 $M=10\times\max|c|$；**不要用 $10^{15}$**（会破坏数值稳定性） | 〔推理〕通用经验 |
| **"一对多"指派** | 复制列 $k$ 次（每个执行者可接 $k$ 个任务）；或用**最小费用流**建模（更自然） | 〔推理〕通用经验 |
| **多目标** | 加权和（需做权重敏感性分析）；或字典序（先最小化换乘/次数，再最小化时间）；或瓶颈指派（二分 + 判定） | 〔推理〕通用经验 |
| **数值预处理** | 代价矩阵**行/列减去各自最小值**（这是匈牙利算法的标准预处理，同时降低数值范围） | 〔推理〕通用经验 |
| **规模上限** | $n\le2000$ 用 KM 或 `linear_sum_assignment`；$n>5000$ 考虑稀疏化或改用最小费用流 | 〔推理〕通用经验 |
| **国赛相关的建模先例** | 〔原文〕`2011B：交巡警服务平台的设置与调度（3）`："由问题特点可以将此问**转化为最优指派优化最长封堵时间的问题**" | 〔原文〕`2011B 交巡警（3）` |

**调参坑**：
- **非方阵不补齐直接调用** → 报错或用错算法（有些实现会自动补，行为不确定）。
- **补零与补大 $M$ 混用** → 结果中"未指派"与"强制指派"混淆，业务上说不通。
- **大 $M$ 取到 $10^{15}$** → 与真实代价相加后浮点精度丢失，可能产生错误的最优解。
- **忘记"行/列减最小值"** → 数值范围大时精度下降（虽然现代实现会自动做）。
- **把"每个平台可封锁多个路口"当成标准指派** → 会得到"一个平台只能封一个路口"的错误结论；必须复制行或改最小费用流。

## 6. 优点

1. **精确、全局最优、可证明**：返回最优指派并可通过 $u_i+v_j\le c_{ij}$ 的对偶可行性直接证明最优性。**这是它相对所有启发式方法的根本优势**。
2. **多项式时间 $O(n^3)$**，规模几百到上千毫无压力。
3. **实现极其成熟**：`scipy.optimize.linear_sum_assignment`（C++ 实现，极快）、`networkx.algorithms.bipartite.minimum_weight_full_matching`、MATLAB `matchpairs`。
4. **无参数需要调**：不像 GA/SA 要调一堆参数，匈牙利算法给定矩阵就有确定结果，**完全可复现**。
5. **结构优美**：全幺模性保证了 LP 松弛即整数，这一点在论文中非常值得点明（体现对问题结构的理解）。
6. **可与其他模型衔接**：指派结果可以作为更大模型（选址、调度）的子模块反复调用。
7. **对偶变量的物理意义清晰**：行势/列势可以解释为"任务的影子价格""执行者的机会成本"，是灵敏度分析的好材料。

## 7. 缺点

1. **只能处理"一一对应"的指派结构**：一旦出现"容量约束""时间窗""顺序相关"（如"任务 B 必须在 A 之后"），标准匈牙利算法就不再适用，须升级为最小费用流或整数规划。
2. **必须是线性目标**：若代价依赖"成对组合"（如"A 和 B 必须分给同一人"），需要二次指派（QAP），那是 NP 难的，匈牙利算法无效。
3. **方阵要求**：非方阵必须补齐，而补齐方式影响结果的业务含义。
4. **多目标支持差**：加权和需要主观权重；瓶颈型目标需要额外处理。
5. **代价矩阵规模 $O(n^2)$ 内存**：$n=10^5$ 时 80 GB，不可行（此时通常问题本身也稀疏，应改用最小费用流）。
6. **国赛语料中检索不到该名称**：见第 11 节——**若论文只写"匈牙利算法"而不解释，评审可能无法把它与你实际建模的 0-1 规划对应起来**；反过来，若你写"0-1 规划 + LINGO"，又与语料主流一致但不突出算法亮点。
7. **不处理不确定性**：代价矩阵有随机性时需要随机指派模型。

## 8. 适用规模与适用条件

**适用条件**：
- 问题是**标准的 $n\times n$ 一对一指派**；
- 目标与约束**线性**，代价矩阵**已知且确定**；
- 所有执行者与任务的**代价可量化**（能构造出数值矩阵）；
- 无顺序依赖、无容量限制（或能通过复制行列转化为标准形式）；
- 规模 $n\le2000$（更大时用最小费用流或稀疏实现）。

**适用规模**：$n=10\sim2000$；内存 $O(n^2)$；时间从微秒（$n=50$）到数十秒（$n=2000$）。

**国赛典型场景**〔归纳〕：交巡警平台与路口的封堵指派、任务与人员的匹配、设备与工序的匹配、比赛对手安排、评委与论文分配。

## 9. 不适用情况

- **一对多 / 多对一 / 容量约束**（每个执行者可做多个任务，但有容量上限）：应建**最小费用流**或整数规划。
- **带时间窗/顺序约束**（任务必须按序执行）：调度问题，应建整数规划或启发式。
- **二次指派（QAP）**（代价依赖组合）：NP 难，匈牙利算法无效。
- **三方匹配**（人-任务-时间段三方）：三维指派是 NP 难的。
- **$n$ 极大（$>10^4$）**：$O(n^2)$ 内存与 $O(n^3)$ 时间都不可行；应利用稀疏性改用最小费用流。
- **代价不确定/随机**：需随机规划或鲁棒优化。
- **目标是"最小化最大值"且需精确最优**：需瓶颈指派算法（阈值二分 + 二分图匹配），不是标准匈牙利算法。
- **问题本身不是指派结构**（如选址、路径）：不要硬套。

## 10. Python / MATLAB 实现要点

**Python**
- **首选**：`from scipy.optimize import linear_sum_assignment`；`row_ind, col_ind = linear_sum_assignment(C)`；`total = C[row_ind, col_ind].sum()`。
  - 基于 Jonker–Volgenant 算法，**比手写 KM 快得多**，支持非方阵（自动补齐）、支持负值、支持最大化（`maximize=True`）。
  - **这是国赛实现指派问题的推荐做法**。
- `networkx`：`nx.algorithms.bipartite.minimum_weight_full_matching(G)`，适合稀疏场景。
- 手写 KM 主要用于教学/论文展示；**不要在生产代码里用手写版**（细节多、易错）。
- 大 $M$ 禁止指派时，取 `M = 10 * C.max()`，并在结果中检查是否真的指派到了 $M$ 位置。
- 建 LP 版本：`scipy.optimize.linprog` 或 `pulp`，可顺带拿到对偶变量做灵敏度分析。
- 多目标（瓶颈型）：对阈值 $T$ 二分，把 $c_{ij}>T$ 的边置为不可用，调用 `linear_sum_assignment` 判断是否存在完美匹配（用大 $M$ 检测），$O(\log T)$ 次调用。

**MATLAB**
- `matchpairs(C, costUnmatched)` （R2019a+）：`matchpairs(C, 1e6)` 返回匹配对 `M`（每行一个 [i j]）；`costUnmatched` 是"不匹配"的代价。
- 传统做法：`assignDetectionsToTracks`（Computer Vision Toolbox，本质也是指派）。
- 建 0-1 规划：`intlinprog`，但**注意由于全幺模性，用 `linprog` 就能得到整数解**，且更快。
- LINGO 写法（国赛主流）：
  - `SETS: TASK/1..n/; WORKER/1..n/; LINK(TASK,WORKER): c, x; ENDSETS`
  - `MIN = @SUM(LINK: c*x);`
  - `@FOR(TASK(i): @SUM(WORKER(j): x(i,j)) = 1);`
  - `@FOR(WORKER(j): @SUM(TASK(i): x(i,j)) = 1);`
  - `@FOR(LINK: @BIN(x));`
- 画图：指派结果的**二分图连线图**（左边任务、右边执行者，匹配边加粗）或**指派矩阵热力图**。

## 11. 国赛论文中的写法与案例

### 推荐句式（可直接套用）

> 该问题可转化为标准的指派问题：将（服务平台）视为执行者、将（路口）视为任务，代价 $c_{ij}$ 表示（第 $i$ 个平台封锁第 $j$ 个路口所需的时间）。建立 0-1 规划模型：$\min\ \max_{i,j}\{c_{ij}x_{ij}\}$（或 $\min\sum\sum c_{ij}x_{ij}$），s.t. $\sum_j x_{ij}=1$，$\sum_i x_{ij}=1$，$x_{ij}\in\{0,1\}$。

> 由于指派问题的约束矩阵为全幺模矩阵，其线性规划松弛的最优解必然为整数解，因此该 0-1 规划可直接用线性规划方法精确求解，无需分支定界。本文采用（匈牙利算法 / 调用求解器）求解，得到最优指派方案见表 x，最短封锁时间为 $\cdot$ 分钟。

> （若用匈牙利算法）本文采用匈牙利算法（Kuhn–Munkres 算法）求解该指派问题。算法的时间复杂度为 $O(n^3)$，本题 $n=\cdot$，可在（$\cdot$）毫秒内求得全局最优指派。为验证最优性，本文检验了对偶可行性条件 $u_i+v_j\le c_{ij}$ 对全部 $(i,j)$ 成立且对所有被指派边取等号，从而确认所得解为全局最优。

> （若做瓶颈指派）由于本题目标为"最小化最长封锁时间"，属于瓶颈指派问题，本文采用二分法求解：给定阈值 $T$，将 $c_{ij}>T$ 的指派视为不可行，判断是否存在完美匹配；二分搜索最小的可行 $T$，得到最优值为 $\cdot$ 分钟。
