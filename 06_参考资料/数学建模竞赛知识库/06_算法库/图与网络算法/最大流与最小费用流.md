# 最大流与最小费用流

> **证据等级约定**：〔原文〕= 在语料文件中直接读到原句；〔归纳〕= 由多篇语料归纳出的共性；〔推理〕= 语料未直接支持，按通用算法经验给出。
> **语料范围**：`_work_extract\*.txt`（1992—2025 国赛真题+优秀论文）、`_work_extract\_keydocs\*.txt`（方法汇总）、`_work_extract\2026真题\*.txt`。
> 本文只读语料、不改原文；所有"优秀论文案例"均为实际检索命中，未命中一律标【资料中未找到直接案例】。


## 1. 算法解决什么问题

**网络流问题**——把"资源从供给点经网络输送到需求点"抽象成带容量的有向图。

- **最大流（Max Flow）**：在每条边容量 $u_{ij}$ 的限制下，求从源点 $s$ 到汇点 $t$ 能输送的**最大流量**。
  $$\max\ v\quad \text{s.t.}\quad \sum_j f_{ij}-\sum_j f_{ji}=\begin{cases}v,&i=s\\-v,&i=t\\0,&\text{其他}\end{cases},\quad 0\le f_{ij}\le u_{ij}$$
- **最小费用流（Min-Cost Flow, MCF）**：在满足给定流量（或最大流）的前提下，**使总运输费用最小**。
  $$\min\ \sum_{(i,j)}c_{ij}f_{ij}\quad \text{s.t.}\quad \text{流量守恒},\ 0\le f_{ij}\le u_{ij}$$
- **最小费用最大流**：先求最大流，再在所有最大流中找费用最小者（国赛语料中的标准提法）。

**对偶与最优性（论文中值得点明）**：
- **最大流最小割定理**：最大流值 = 最小割容量。**这给出一个可验证的最优性证书**——找到任意一个割集，其容量等于流量，即证明最优。
- **负费用回路最优性条件**：一个流是最小费用流 $\iff$ 其残量网络中**不存在负费用回路**。

**国赛里的落点**〔归纳〕：
1. **DVD/物资分配**（"每个会员最多租 3 张"+"每张碟只有 1 份"→ 二分图容量网络）——**语料中最标准的应用**；
2. **运输与调运网络**（钢管订购运输、多级配送）；
3. **任务分配与匹配**（可归约为二分图最大流）；
4. **调度可行性判定**（用最大流判断"能否在期限内完成全部任务"）。

## 2. 输入与输出

**输入**
- 有向图 $G=(V,E)$、源点 $s$、汇点 $t$；
- **每条边的容量 $u_{ij}$**（供给上限/道路通行能力/库存量）；
- （最小费用流）**每条边的单位费用 $c_{ij}$**；
- （有下界时）边流量的下界 $l_{ij}$——需先转化为标准形式（见第 3.4 节）。

**输出**
- **最大流量 $v^*$**；
- （MCF）**最小费用**及最优流分配 $\{f_{ij}\}$；
- **最小割集 $S^*$**（最大流问题）——即瓶颈所在；
- （对偶）节点势 $\pi_i$，对应"影子价格"。

**国赛建模的关键（不是算法，而是如何建网络）**：
1. **"一一对应"约束** → 边容量 1；
2. **"最多 k 次"约束** → 边容量 $k$；
3. **"必须完成"约束** → 给该需求点加一条"需求下界边"或事后检查是否满载；
4. **"不可行"** → 容量 0 或删边；
5. **点容量限制**（如"某个中转站最多处理 100 单位"）→ **拆点**：把节点 $i$ 拆成 $i_{\text{in}}\to i_{\text{out}}$，该边容量即点容量。

## 3. 算法步骤（伪代码级）

### 3.1 最大流：Dinic 算法（$O(V^2E)$，实用最快之一）

1. 初始化残量网络：对每条边 $(u,v,u_{uv})$，设 $f_{uv}=0$；残量 $r_{uv}=u_{uv}$，反向残量 $r_{vu}=0$。
2. **循环**：
   1. **BFS 分层**：从 $s$ 做 BFS，只走残量 $>0$ 的边，得到每个节点的层号 $\text{level}[\cdot]$。**若 $t$ 不可达 → 算法终止，当前流即最大流**。
   2. **DFS 阻塞流**：从 $s$ 出发，只沿"层号递增 1"的残量边做 DFS，找到一个可行流并增广；反复直到该分层图中无增广路（得到阻塞流）。用 $\text{iter}[v]$ 记录当前弧，避免重复扫描。
   3. 把阻塞流累加到总流上，回到步骤 2.1 重新分层。
3. **输出**最大流值 $v^*$，以及各边流量 $f_{uv}=u_{uv}-r_{uv}$。
4. **求最小割**：在最终的残量网络中从 $s$ 做一次可达性搜索，可达集合 $S$ 与补集 $T$ 构成最小割，$\text{cap}(S,T)=v^*$（**最优性证书**）。

### 3.2 最小费用流：SPFA / 势能 Dijkstra（逐次最短路增广）

1. 初始化流 $f=0$，费用 $\text{cost}=0$。
2. **循环**：
   1. **在残量网络中找 $s\to t$ 的最小费用路径**：
      - 若费用可能为负（有反向边）：用 **SPFA（Bellman-Ford 队列版）**，$O(VE)$；
      - 若无负费用：用 **Dijkstra + 势能函数**（Johnson 势），$O(E\log V)$。
   2. 若 $t$ 不可达，终止。
   3. **取增广量** $\delta=\min$ 路径上所有边的残量。
   4. **增广**：路径上正向边减 $\delta$、反向边加 $\delta$；$f\leftarrow f+\delta$；$\text{cost}\leftarrow\text{cost}+\delta\cdot(\text{路径费用})$。
   5. （若只求"给定流量的最小费用"且已达目标流量，终止）
3. **输出**流量、费用、流分配。
4. **最优性验证**：检查残量网络中**不存在负费用回路**——满足即证明最小费用最优。

### 3.3 最小费用最大流（国赛语料的标准提法）

1. 先用 Dinic / 增广路求**最大流 $v^*$**（或直接进入第 2 步，因为逐次最短路增广法会自动同时给出最大流）。
2. 用 3.2 的逐次最短路增广：**每步都选费用最小的增广路**，持续到 $t$ 不可达。
3. 此时得到的既是**最大流**，又是**所有最大流中费用最小者**。
4. 输出 $v^*, \text{cost}^*$ 与流的分配方案。
5. **注意**：若存在负费用边，必须先做"消负圈"处理，或改用 SPFA。

### 3.4 有下界的网络流（转化为标准形式）

1. 对每条边 $(u,v)$，设下界 $l$、上界 $u$；令 $u'=u-l$（容量减去下界）。
2. 令 $d_v=\sum_{\text{入}}l-\sum_{\text{出}}l$（节点的"净需求"）。
3. 建立超级源 $S$、超级汇 $T$：若 $d_v>0$，加边 $(S,v,d_v)$；若 $d_v<0$，加边 $(v,T,-d_v)$。
4. 从 $S$ 到 $T$ 求最大流；**若该最大流等于 $\sum_{d_v>0}d_v$，则存在可行流**，否则无可行流。
5. 得到可行流后，再去掉 $S,T$，按目标（最大流/最小费用）继续优化。

## 4. 复杂度与收敛性

| 算法 | 时间复杂度 | 空间 | 适用 |
|---|---|---|---|
| Ford–Fulkerson（DFS 增广） | $O(E\cdot v^*)$，**与流量值有关，可能极慢** | $O(V+E)$ | 仅教学 |
| Edmonds–Karp（BFS 增广） | $O(VE^2)$ | $O(V+E)$ | 简单可靠 |
| **Dinic** | $O(V^2E)$（单位容量图 $O(E\sqrt V)$） | $O(V+E)$ | **实用首选** |
| Push–Relabel（最高标号预流推进） | $O(V^2\sqrt E)$ | $O(V+E)$ | 大规模稠密图 |
| **SPFA 逐次最短路（MCMF）** | $O(F\cdot VE)$，$F$ 为最大流量 | $O(V+E)$ | 有负费用时 |
| **Dijkstra + 势能（MCMF）** | $O(F\cdot E\log V)$ | $O(V+E)$ | 无负费用时的首选 |
| 网络单纯形 / 成本缩放 | 实践中比逐次增广快几个数量级 | $O(V+E)$ | 大规模 MCF，商业求解器内核 |

**收敛性（必须写对）**：
1. **最大流与最小费用流都是精确算法**（在整数容量下），给出的是**全局最优解**；且**整数容量 ⇒ 存在整数最优流**（全幺模性），所以不会被"半条边"困扰。
2. **最大流最小割定理**给了一个**可验证的最优性证书**：找到容量等于流量的割，即证明最优。**这是网络上唯一能"当场自证最优"的一类问题**。
3. **最小费用流的最优性条件是"残量网络中无负费用回路"**，同样可验证。
4. **Ford–Fulkerson 的复杂度依赖流量值**：若容量是实数或流量很大，可能不终止或极慢——**必须用 Edmonds–Karp / Dinic，而不是朴素 DFS 增广**。
5. **负费用边**：逐次最短路法要求每步都能正确求最短路；有负边时必须用 SPFA（Bellman-Ford），否则 Dijkstra 会失效。

## 5. 参数与调参要点

网络流算法本身**参数极少**，需要决策的是**建模参数**：

| 参数/决策 | 推荐做法 | 依据 |
|---|---|---|
| **容量 $u_{ij}$ 的设定** | 必须来自题目的硬约束（库存量、通行能力、每位会员最多 3 张）。**单位要统一**（张/吨/辆） | 〔推理〕通用经验 |
| **费用 $c_{ij}$ 的设定** | 可为负（负费用边会破坏 Dijkstra，需用 SPFA）；多项费用用加权和，需做敏感性分析 | 〔推理〕通用经验 |
| **源/汇的连接** | 源 → 供给方（容量=供给量）；需求方 → 汇（容量=需求量）；需求必须全部满足时用"下界边"或事后检查 | 〔推理〕通用经验 |
| **点容量** | **拆点**：$i_{\text{in}}\to i_{\text{out}}$，容量=点容量，费用=0（或该点的处理费用） | 〔推理〕通用经验 |
| **层数/级数** | 多层网络用"复制节点层"的方式展开（时间展开网络） | 〔推理〕通用经验 |
| **不可行判定** | 若最大流 $<$ 总需求，说明**需求无法全部满足**；论文中必须报告这一点，而不是硬说"方案可行" | 〔推理〕通用经验 |
| **数值精度** | 容量尽量用**整数**（保证整数最优流）；费用可为浮点 | 〔推理〕通用经验 |
| **规模上限** | Dinic 可处理 $V=10^4,E=10^5$；MCMF 逐次增广在流量大时慢，建议用 `networkx` 的 `min_cost_flow`（网络单纯形）或 OR-Tools | 〔推理〕通用经验 |
| **国赛原文的建模方式** | 〔原文〕`2005B`："设加权有向图中 $G=(V,E)$，$V$ 中除两个特殊（点外…）……在 source 与所有的（会员）之间添加有向边 (source,（会员）)……因此，图 1 中 $G$ 是一个**整数流量的最小费用最大流模型**" | 〔原文〕`2005B：DVD租赁问题的模型设计及求解` |

**调参坑**：
- **把容量设成浮点** → 可能得不到整数流，业务上"半张碟"没有意义（虽然最优值可能仍是整数）。
- **忘记拆点处理"点容量"** → 得到违反点容量约束的"最优解"。
- **源/汇方向接反** → 最大流为 0，且不报错。
- **用朴素 DFS 增广（Ford–Fulkerson）** → 在特定图上迭代次数正比于流量值，可能跑几百万次。
- **需求未全部满足却声称"最优方案"** → 应明确指出"最大流 $=v^*<$ 总需求 $\cdot$，因此存在 $\cdot$ 单位的需求无法满足"。
- **MCMF 用 Dijkstra 但图中有负费用边** → 得到错误的"最短路"。
- **迭代次数按"增广路径数"估计运行时间** → 实际路径数可能远大于 $V$（这正暴露了算法的复杂度问题）。

## 6. 优点

1. **精确、全局最优、可自证**：最大流最小割定理给出可验证的最优性证书，这是极少数能"当场证明最优"的算法族。
2. **多项式时间**：Dinic $O(V^2E)$、MCF 多项式时间，规模上万无压力。
3. **整数性自动保证**：整数容量 ⇒ 存在整数最优流（全幺模性），无需分支定界。**这是相对 0-1 规划的巨大优势**。
4. **建模能力极强**：容量、费用、下界、点容量、时间展开——几乎所有"资源分配/输送"问题都能建模为网络流。
5. **对偶信息丰富**：最小割 = 瓶颈集合；节点势 = 影子价格。**两个都是论文里极有分量的分析素材**。
6. **实现成熟**：`networkx.maximum_flow` / `min_cost_flow`（网络单纯形）、`scipy.sparse.csgraph.maximum_flow`、Google OR-Tools。
7. **国赛接受度高且有"高分先例"**：〔原文〕`2005B：DVD租赁问题的模型设计及求解` 的编者按明确写道"问题二、三的通常解法是用 LINGO 软件求解 0-1 规划模型，**本文另辟蹊径，成功地用网（络流方法）…最小费用最大流方法，得到了令人满意的结果。体现了作者较强的创新意识和能力**"。**这是评委明确认可"用网络流替代 0-1 规划"的一手证据**，价值极高。

## 7. 缺点

1. **只能处理"网络结构"的问题**：目标必须是"流的线性费用"，约束必须是"守恒 + 容量"。带时间窗、顺序依赖、批次约束的调度问题无法直接套。
2. **建模难度高**：把实际问题翻译成网络（尤其是拆点、下界、时间展开）需要相当的技巧，**建模错一步结果全错且不报错**。
3. **非线性费用不支持**：若费用与流量的关系是非线性的（如阶梯电价、规模经济），标准 MCF 失效，需要分段线性化近似。
4. **逐次增广法的复杂度依赖流量 $F$**：$F=10^6$ 时会很慢（需要改用成本缩放/网络单纯形）。
5. **多商品流是 NP 难的**：多个互不混同的商品共享同一网络时，问题是 NP 难的，不能用单商品流算法。
6. **负费用边处理麻烦**：必须用 SPFA 或先消负圈。
7. **结果解释门槛高**：评委若对网络流不熟，需要论文写清每次增广的含义（用 2005B 的写法：把 source→会员→DVD→terminal 的每一层都解释清楚）。
8. **调试困难**：模型正确性主要靠"结果是否符合业务常识"来判断，缺少自动检查手段。

## 8. 适用规模与适用条件

**适用条件**：
- 问题可以建模为**有向图上的流量守恒**；
- 约束都是**容量约束**（每条边一个上限），无顺序/时间窗依赖；
- 目标是**流量的线性函数**（最大化流量 或 最小化 $\sum c_{ij}f_{ij}$）；
- 容量为**整数**（保证整数最优流）；
- 网络规模 $V\le10^4$、$E\le10^5$（Dinic）；MCF 规模更小一些或需用高效实现。

**适用规模**：$V=10^2\sim10^4$，$E=10^3\sim10^5$；最大流秒级；MCF 取决于流量值与费用范围，通常秒到分钟。

**国赛典型场景**〔归纳〕：DVD/图书/物资分配、运输调运网络、任务分配与匹配、可行性与瓶颈判定。

## 9. 不适用情况

- **带时间窗 / 顺序依赖的调度问题**：需时间展开网络（规模爆炸）或直接建整数规划。
- **非线性费用**（阶梯定价、规模经济）：需分段线性化近似，精度受限。
- **多商品流**（多种不能混同的货物共享网络）：NP 难，需启发式或列生成。
- **问题没有明确的"流量守恒"结构**（如选址、排序、覆盖）：不要硬套。
- **需要"整数但非网络结构"的组合约束**（如"A 与 B 必须同时选"）：整数规划更合适。
- **规模极小（$V\le10$）**：直接枚举或 LP 更快，用网络流是过度设计。
- **只需要可行性而不需最优**：简单的贪心/二分判定可能更快。
- **赛题要求"给每个方案打分排序"**：那是评价类问题，与网络流无关。

## 10. Python / MATLAB 实现要点

**Python**
- **`networkx`**：
  - 最大流：`nx.maximum_flow(G, s, t, capacity='capacity')` → 返回 `(flow_value, flow_dict)`；
  - 最小割：`nx.minimum_cut(G, s, t, capacity='capacity')` → 返回 `(value, (S, T))`——**直接拿到瓶颈集合**；
  - 最小费用流：`nx.min_cost_flow(G, demand='demand', capacity='capacity', weight='weight')`；**`demand` 属性是节点需求（正=需求，负=供给）**，用 `G.add_node(v, demand=...)` 设置；
  - `nx.max_flow_min_cost(G, s, t)` 求最小费用最大流。
- **`scipy.sparse.csgraph.maximum_flow(csgraph, source, sink)`**：C 实现，大规模更快。
- **Google OR-Tools**：`pywrapgraph.SimpleMinCostFlow()`，网络单纯形实现，工业级。
- **手写 Dinic** 用于理解与教学；注意 `level` 分层 + `iter` 当前弧优化是性能关键。
- 建图时给边加 `capacity`、`weight` 属性；**拆点用 $i$ 与 $i+n$ 两个编号**。
- 负费用边：`networkx.min_cost_flow` 用网络单纯形，可以处理负权（但不能有负费用回路）。
- 结果检验：`flow_value == nx.minimum_cut_value(...)` ——**用最小割验证最大流，一行代码完成最优性自检**。

**MATLAB**
- `maxflow(G, s, t)`（R2015b+，`G` 为 `digraph`）→ `[mf, GF, CS, CT] = maxflow(G, s, t)`；`CS, CT` 即**最小割的两侧节点**。
- 无内置最小费用流函数；可用 `optimproblem` + `optimvar` 建 LP 求解（**由于网络矩阵全幺模，`linprog` 即可得整数解**），或调用第三方实现（File Exchange 上的 `min_cost_flow`）。
- 建图：`G = digraph(s, t, capacity)`；`G.Edges.Weight = cost`。
- 画图：`plot(G, 'EdgeLabel', G.Edges.Weight, 'LineWidth', 2)`，按流量粗细映射边宽——**一张图讲清整个流分配**。
- 老国赛代码常用 LINGO 建模网络流（把网络写成 0-1/整数规划），注意 LINGO 求解大规模网络流时不如专用算法快。

## 11. 国赛论文中的写法与案例

### 推荐句式（可直接套用）

> 本文将问题抽象为网络流模型。构造有向图 $G=(V,E)$：源点 $s$ 连接各（供给方 / 会员），容量为该（供给方的供给量 / 会员的租赁上限）；各（供给方）连接各（需求方 / 碟片），容量为（是否可分配，取 0 或 1）；各（需求方）连接汇点 $t$，容量为（需求量）。由于所有容量均为整数，该网络中必存在整数最优流。

> （若求最大流）本文采用 Dinic 算法求解最大流，时间复杂度为 $O(V^2E)$。求得最大流 $v^*=\cdot$。根据最大流最小割定理，本文进一步求出了最小割 $S^*=(\cdot)$，其容量等于 $v^*$，从而证明了 $v^*$ 确为最大流。最小割对应的（边集）即为当前系统的瓶颈所在。

> （若求最小费用最大流）由于本题需在满足全部（需求）的前提下使总（运输费用）最小，属于最小费用最大流问题。本文采用逐次最短路增广算法：每步在残量网络中求 $s\to t$ 的最小费用路径并沿其增广，直至不存在增广路。求得最大流 $v^*=\cdot$，最小总费用为 $\cdot$ 元。为验证最优性，本文检查了最终残量网络中不存在负费用回路，满足最小费用流的最优性条件。

> （若需求未全部满足）求解结果表明最大流 $v^*=\cdot<$ 总需求量 $\cdot$，说明在现有（资源/容量）约束下无法满足全部需求，缺口为 $\cdot$ 单位；对应的最小割指出了制约系统输送能力的关键（路段/环节）。

### 配图建议
1. **网络结构图 + 流分配**：源点、中转层、汇点三列布局，边的**粗细表示流量大小**、**颜色表示饱和度**（流量/容量）；这是网络流论文的主图。
2. **最小割可视化**：用虚线把网络切成 $S$ 和 $T$ 两部分，割边用红色高亮，标注"割容量 = 最大流 = $v^*$"——**极强的理论说服力**。
3. **饱和边统计图**：哪些边满载（瓶颈）、哪些边空闲，柱状图或网络图着色。
4. **费用-流量曲线**：横轴流量约束值，纵轴最小费用（分段线性、凸函数），展示边际成本递增。
5. **与其他解法对比表**：网络流 vs 0-1 规划（LINGO）的求解时间与结果一致性。
