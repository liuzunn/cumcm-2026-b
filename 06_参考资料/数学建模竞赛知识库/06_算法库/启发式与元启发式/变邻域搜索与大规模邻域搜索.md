# 变邻域搜索与大规模邻域搜索

## 1. 算法解决什么问题

**在已有可行解的基础上做系统性局部改进**，适合"已经有还不错的解，想再往下压一压"的场景。二者是姊妹方法，常被混称，但机制不同：

- **变邻域搜索（Variable Neighborhood Search, VNS）**：**换邻域结构**而不是换解。核心思想是"一个邻域里的局部最优，往往不是另一个邻域里的局部最优"——因此依次用 $N_1,N_2,\dots,N_{k_{\max}}$ 多个邻域做下降搜索，一旦某个邻域改进了就回到 $N_1$ 重新开始。变体 **VND（变邻域下降）** 是纯下降版本，**RVNS** 是随机化版本。
- **大规模邻域搜索（Large Neighborhood Search, LNS）**：**把解"破坏"一大块再"修复"**。用 destroy 算子随机/启发式地移除 10%～40% 的决策分量，再用 repair 算子重新插入，得到一个差异很大的新解；接受则更新。其自适应版本 **ALNS** 会根据算子的历史表现动态调整各算子的选择概率。

**两者在国赛中的定位**〔归纳〕：它们**不是用来从零求解的**，而是**接在贪心/启发式之后做精修的"最后一公里"工具**。国赛语料中的 RGV 调度、测线布设、碎纸拼接等题，其"多阶段贪心 + 剪枝搜索"的写法在精神上非常接近 VND。

## 2. 输入与输出

**输入**
- 一个**可行初始解** $x_0$（VNS/LNS 都需要，绝不能从零开始）；
- 目标函数 $f(x)$ 与可行性判定/修复函数；
- **VNS**：邻域结构集合 $\{N_1,\dots,N_{k_{\max}}\}$（如 $N_1$=交换两点，$N_2$=逆序一段，$N_3$=插入一段）；
- **LNS/ALNS**：destroy 算子集合 $\{\mathcal D_1,\dots\}$、repair 算子集合 $\{\mathcal R_1,\dots\}$、移除比例 $q$、算子权重更新参数；
- 接受准则（VND 用"只接受改进"；LNS 可用"接受改进"或 SA 式概率接受）；
- 最大迭代 / 时间上限。

**输出**
- 改进后的解 $x^*$ 与目标值；
- **改进轨迹**：初始解目标值 → 迭代过程中的目标值序列；
- （ALNS）各算子的累计使用次数与成功率——**这是论文里非常有说服力的表格**。

## 3. 算法步骤（伪代码级）

### 3.1 基本 VNS（变邻域下降 VND 版本，最常用）

1. 输入初始解 $x\leftarrow x_0$，邻域结构集合 $N_1,\dots,N_{k_{\max}}$。
2. **循环** 直到所有邻域都无法改进：
   1. $k\leftarrow1$。
   2. **当 $k\le k_{\max}$**：
      1. **抖动/搜索**：在当前解的第 $k$ 个邻域内生成候选 $x'\leftarrow$ 在 $N_k(x)$ 中最优（或随机采样若干）的解。
      2. **局部搜索（可选但推荐）**：对 $x'$ 施加基础局部搜索（如 2-opt 到局部最优），得到 $x''$。
      3. **接受判定**：若 $f(x'')<f(x)$：
         - $x\leftarrow x''$；
         - **$k\leftarrow1$**（回到最小邻域重新开始——**这是 VNS 的灵魂**）；
         否则 $k\leftarrow k+1$（换下一个邻域）。
   3. 若 $k>k_{\max}$ 且本轮无任何改进，终止。
3. 输出 $x$ 与其目标值。

### 3.2 基本 LNS / ALNS

1. 输入初始解 $x\leftarrow x_0$，$x^*\leftarrow x$；初始化各 destroy/repair 算子权重 $w_i\leftarrow1$；温度或接受参数。
2. **循环** 对 $t=1\dots T_{\max}$：
   1. **选算子**：按权重 $w_i$ 用轮盘赌选一对 $\mathcal D_i,\mathcal R_j$。
   2. **Destroy（破坏）**：从 $x$ 中移除 $q=\lceil\rho\cdot n\rceil$ 个决策分量（$\rho=0.1\sim0.4$）。移除策略：
      - 随机移除；最差移除（移除对目标贡献最差的）；Shaw 移除（移除相似的、空间相邻的）；整段移除。
   3. **Repair（修复）**：用贪心/最近邻/插入代价最小等策略把移除的分量重新插入，得到 $x'$。（**必须保证 $x'$ 可行**）
   4. **接受判定**：若 $f(x')<f(x)$ 则接受；否则以概率 $\exp(-(f(x')-f(x))/T)$ 接受（SA 式）或以小概率接受。
   5. **更新最优**：若 $f(x')<f(x^*)$，$x^*\leftarrow x'$。
   6. **更新算子权重**：按预设的评分规则（新最优 +33、改进当前解 +9、被接受但未改进 +3、被拒绝 +0），并做权重平滑 $w_i\leftarrow(1-\eta)w_i+\eta\cdot\text{score}_i/\text{used}_i$（$\eta=0.1$）。
3. 输出 $x^*$。
4. **可信度检验**：VNS 是确定性/半确定性的；LNS 需多次运行报告统计量。

## 4. 复杂度与收敛性

| 指标 | VNS | LNS / ALNS |
|---|---|---|
| 时间复杂度 | 每轮 $O\big(\sum_k \|N_k(x)\|\cdot c_f\big)$；总 $O(T\cdot\sum_k\|N_k\|\cdot c_f)$ | 每次迭代 $O(q\cdot n\cdot c_{\text{repair}})$，$q=\rho n$ |
| 空间复杂度 | $O(\text{解长})$ | $O(\text{解长}+\text{算子数})$ |
| 收敛性 | **确定性**（VND 版本）：给定初值结果唯一 | 随机（ALNS 有权重自适应） |
| 最优性 | 无全局最优保证；但**只要邻域集合"覆盖"了所有可能改进方向，VND 收敛到的解就是所有邻域联合意义下的局部最优**（这是一个比"单一邻域局部最优"更强的结论） | 无最优保证 |
| 收敛速度 | 快，通常几十到几百轮 | 中等，需要几百到几千次 destroy-repair |

**必须写进论文的结论**：
1. **VND 的收敛点比普通局部搜索强**：它是 $\bigcup_k N_k$ 意义下的局部最优。论文中可写"所得解在所有设定的邻域结构下均无法进一步改进"，这个措辞**严格且有力**。
2. **VND 是确定性的**（若邻域全枚举），结果可复现，不需要多种子统计——与禁忌搜索同属"确定性改进型算法"。
3. **LNS 的破坏-修复机制使其能跳出局部最优**，因为移除 30% 的分量后，修复过程往往会选到与原来完全不同的组合。
4. **ALNS 的算子权重自适应是关键**：它把"哪个破坏算子有用"这件事交给数据决定，避免了人工调参。
5. **两者的共同前提是"有初始可行解"**：它们做的是 **intensification（强化）**，不是 **diversification（多样化）**；若初始解很差，它们改不出好结果。

## 5. 参数与调参要点

| 参数 | 推荐取值区间 | 依据 |
|---|---|---|
| **VNS 邻域个数 $k_{\max}$** | 3～6（太多会导致每轮开销大而收益递减） | 〔推理〕通用经验 |
| **VNS 邻域设计** | 从小到大排列：$N_1$ 扰动 1 个分量、$N_2$ 扰动 2 个、$N_3$ 扰动一段——**规模递增是 VNS 的标准做法** | 〔推理〕通用经验 |
| **VNS 抖动强度** | 第 $k$ 个邻域扰动幅度约为 $k$ 个分量（或 $k\cdot0.05n$） | 〔推理〕通用经验 |
| **VNS 局部搜索** | 每次抖动后做一次基础局部搜索（如 2-opt 到局部最优），效果提升显著 | 〔推理〕通用经验 |
| **LNS 移除比例 $\rho$** | 0.1～0.4（常用 0.2～0.3）；太小学不到新结构，太大退化为重新构造 | 〔推理〕通用经验 |
| **ALNS 权重更新参数** | 反应因子 $\eta=0.1$；评分 33/9/3/0；每 $\cdot$ 次迭代归一化一次权重 | 〔推理〕通用经验（Ropke & Pisinger 经典设置） |
| **ALNS 接受准则** | 改进接受 + SA 式小概率接受劣解，$T$ 从初始解目标值量级的 5% 起线性降到 0.1% | 〔推理〕通用经验 |
| **最大迭代** | VNS：500～5000 轮；LNS：2000～50000 次 destroy-repair | 〔推理〕通用经验 |
| **初始解** | **必须由贪心/启发式给出**；VNS/LNS 不做从零构造 | 〔推理〕通用经验 |
| **可复现性** | VNS 固定邻域枚举顺序 → 完全确定；LNS 需固定种子 | 〔推理〕通用经验 |

**调参坑**：
- **没有初始可行解就直接跑 VNS/LNS** → 算法无处可去。必须先用贪心构造。
- **邻域不递增** → VNS 退化为普通局部搜索，失去"换邻域跳出"的核心价值。
- **改进后不重置 $k\leftarrow1$** → 会在某个大邻域里耗尽时间，漏掉小邻域的快速改进。
- **LNS 的 destroy 后不检查可行性** → 修复出不可行解，整个结果作废。
- **LNS 移除比例设为 0.9** → 等价于每次重新构造，退化为随机重启。
- **ALNS 权重不归一化** → 权重爆炸或全部归零，算子选择失效。

## 6. 优点

1. **稳定可靠**：只要初始解可行，结果**一定不劣于初始解**——这是它相对 GA/PSO 的重要保障（后者的某次运行可能比初值还差）。
2. **VND 是确定性的**，结果可复现，论文不必报告多种子统计。
3. **VND 的收敛点有清晰的数学含义**（所有邻域的联合局部最优），论文措辞严格。
4. **LNS 能跳出局部最优**：破坏-修复机制比随机扰动的"目的性"强得多，因此 ALNS 在 VRP、排班等经典问题上常优于 GA/SA。
5. **与问题结构耦合度低**：只需定义"移除什么"和"怎么插回"，不需要编码/解码/交叉。
6. **可解释性强**："哪个算子贡献了多少改进"可以做成表格，直接体现工作量。
7. **易于与贪心组合**：**"贪心构造 + VND/LNS 精修"是国赛里性价比最高的求解流水线**。

## 7. 缺点

1. **强依赖初始解质量**：初始解差 → 精修改不动；这也是它们不能单独使用的原因。
2. **VNS 的邻域设计依赖问题**：设计不好（扰动无意义）则完全失效。
3. **超参数仍有若干**（$k_{\max}$、邻域规模、$\rho$、接受温度），ALNS 尤甚。
4. **无全局最优保证**，也没有最优性界。
5. **时间不可预测**：VNS 每轮开销取决于邻域大小，LNS 取决于修复策略；难以给出确定的运行时间上界。
6. **LNS 的实现工作量比 GA/SA 大**，需要写多个 destroy/repair 算子。
7. **国赛语料中几乎没有直接案例**（详见第 11 节），评委可能不熟悉这种提法——虽然其思想与"多阶段贪心 + 剪枝"高度一致，但**用 VNS/LNS 这个名字需要自己把机制讲清楚**。

## 8. 适用规模与适用条件

**适用条件**：
- **已有一个可行初始解**（这是最硬的前提）；
- 问题的**邻域/破坏-修复操作容易定义**（路径、调度、分配、装箱类问题天然满足）；
- 目标函数评价便宜（$\lesssim1$ ms，因为一次 LNS 迭代要评价多次）；
- 解可以**增量评价**（改变局部后只重算受影响部分，大幅加速）；
- 需要"在有限时间内把解压到最好"，而不是"从零求解"。

**适用规模**：决策变量 $n=20\sim10^5$（VND 适合 $n\lesssim10^3$，LNS 适合更大的规模）；迭代 500～50000 次。

## 9. 不适用情况

- **没有可行初始解**：先写贪心，别直接上 VNS/LNS。
- **连续优化**：邻域/破坏-修复在连续空间不自然；用 PSO/DE/梯度法。
- **小规模精确可解问题**（$n\le20$ 的 TSP、0-1 变量 $\lesssim300$ 的 IP）：分支定界/DP 给精确最优，精修没意义。
- **目标函数评价昂贵（$>1$ 秒）**：一次 LNS 迭代要评价多次，无法承受。
- **需要最优性证明**：VNS/LNS 给不出。
- **问题没有可利用的局部结构**（每个决策分量都与其他所有分量强耦合）：破坏-修复会产生大量不可行解，效率崩溃。
- **需要"从零找到一个可行解"**：那是构造启发式（贪心/插入法/节约法）的工作。
- **解空间的可行域极窄**：修复算子很难成功，LNS 迭代大量浪费。

## 10. Python / MATLAB 实现要点

**Python**
- 没有标准库，需自行实现。VND 约 60～100 行；ALNS 约 200～300 行。
- **VND 骨架**：
    1. 定义邻域函数列表 `neighborhoods = [n1, n2, n3]`，每个接受 `(x)` 返回候选解列表或迭代器；
    2. `improved = True`；`while improved:` → `improved = False` → `for k, nk in enumerate(neighborhoods):` → 遍历 `nk(x)` 找最优 → 若优于当前则接受并 `break`（回到 $k=1$）。
- **ALNS 骨架**：
    1. `destroy_ops = [random_removal, worst_removal, shaw_removal]`；`repair_ops = [greedy_insert, regret_insert]`；
    2. 权重数组 `w_d, w_r` + 轮盘赌选择；
    3. 每次迭代记录算子得分，每 100 次更新权重并归一化。
- **增量评价是性能关键**：改变一个分量后只重算受影响的约束/目标项，能把单次迭代从 $O(n)$ 降到 $O(1)$。
- 用 `copy.deepcopy` 或显式复制保存最优解——**列表/数组是引用类型，直接赋值会被后续修改污染**。
- 记录改进轨迹 `history`，画"初始解 → 最终解"的阶梯下降曲线。
- 固定 `random.seed()` 保证可复现。

**MATLAB**
- 无官方实现，需自行编写。VND 用函数句柄数组 `neighborhoods = {@n1, @n2, @n3}` 遍历。
- 解用**行向量**表示（避免 cell 与结构体数组的性能损失）；增量更新用索引运算。
- 用 `randsample` 做算子轮盘赌选择；用 `containers.Map` 或数值数组存权重。
- 画图：改进阶梯曲线、算子贡献柱状图、解的 Gantt 图/路径图。
- 国赛 MATLAB 代码中无 VNS/LNS 先例，**若使用应在论文中给出完整算法流程与伪代码**。

### 推荐句式（可直接套用，仅在你真的实现了时使用）

> 由于（贪心算法 / 启发式规则）得到的解仅为单一邻域意义下的局部最优，本文进一步采用变邻域下降（VND）对其进行改进。定义三个规模递增的邻域结构：$N_1$ 表示交换任意两个任务的执行顺序，$N_2$ 表示将任一任务插入到另一位置，$N_3$ 表示对任一连续片段做逆序。算法自 $N_1$ 开始搜索，一旦找到改进解则立即返回 $N_1$ 重新搜索，否则转入下一个邻域。当所有邻域均无法改进时算法终止。

> 最终解在三个邻域结构下均已无法进一步改进，即它同时是 $\bigcup_{k=1}^{3}N_k$ 意义下的局部最优解。相比初始贪心解，目标值由 $\cdot$ 降至 $\cdot$，改进 $\cdot\%$。

> （若用 ALNS）本文采用自适应大规模邻域搜索（ALNS），设计三种破坏算子（随机移除、最差移除、相似移除）与两种修复算子（贪心插入、后悔值插入），移除比例 $\rho=0.3$。算法根据各算子的历史表现动态调整其被选概率，各算子的累计使用次数与成功改进次数见表 x。

**但存在"思想高度一致"的间接证据**〔原文 + 推理〕：
- `2018B` RGV 调度类论文（见 `_notes\N04_逆向分析_优化调度路径仿真类.md` 的逐篇剖析）中，多篇采用"**多阶段贪心 + DFS 剪枝**""**启发式最近邻 + 254 种刀具配置遍历**""**八步一走前瞻 + 块内枚举**"等写法。这些做法在机制上就是"**在多个规模递增的邻域/决策深度上反复改进**"，**与 VND 的精神一致**，但论文中并未使用"变邻域"这一术语。
- 引用建议：可以引用这些论文作为"**多邻域/多尺度改进在国赛调度题中确实有效**"的支撑，但**不能声称"某篇国赛论文使用了变邻域搜索"**。

**结论与建议**〔推理〕：
1. VNS/LNS 在国赛语料中**没有同名案例，但有同精神的做法**；
2. 最适合的用法是 **"贪心构造 + VND 精修"** 的两段式流水线，这在任何有"移动"定义的题（调度、排班、路径、布设）上都通用；
3. 由于术语陌生，论文中应当**用一句通俗的话解释思想**（"通过依次使用不同规模的邻域结构，使所得解在多个邻域下同时不可改进"），而不是只丢一个缩写。
