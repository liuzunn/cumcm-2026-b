# 贪心与局部搜索

> **证据等级约定**：〔原文〕= 在语料文件中直接读到原句；〔归纳〕= 由多篇语料归纳出的共性；〔推理〕= 语料未直接支持，按通用算法经验给出。
> **语料范围**：`_work_extract\*.txt`（1992—2025 国赛真题+优秀论文）、`_work_extract\_keydocs\*.txt`（方法汇总）、`_work_extract\2026真题\*.txt`。
> 本文只读语料、不改原文；所有"优秀论文案例"均为实际检索命中，未命中一律标【资料中未找到直接案例】。


## 1. 算法解决什么问题

**快速构造一个可行解（贪心），并在此基础上做小幅改进（局部搜索）**。这是国赛里**使用频率最高、性价比最高、也最容易被低估**的一类方法。

- **贪心（Greedy）**：每一步都做"当前看起来最好"的选择，不回退。它不保证最优，但**极快**（通常 $O(n\log n)$ 或 $O(n^2)$），而且**总能给出可行解**——这在时间紧张的比赛中价值极高。
- **局部搜索（Local Search / 爬山法）**：从当前解出发，在邻域内反复移动到更优解，直到没有改进为止。得到的解是"局部最优"。

语料中的定位〔原文 + 归纳〕：
- 〔原文〕`2000年国赛优秀论文_2000B：管道订购与运输问题.pdf.txt`："**改进的最小元素法又称为贪婪法或瞎子爬山法**，它的宗旨是每一步都取当前的最优值"——这是国赛语料中对贪心/爬山最直白的定义。
- 〔原文〕`2012年优秀论文_2012B：太阳能小屋的设计 (5)_基于递归算法的建筑外表面光伏电池布局优化分析与设计.doc.txt`：作者**主动交代了方法的边界**——"基于**贪心原则的递归算法得到的都是局部最优解，并非全局最优解**，但是**时间开销较小**，在数据规模不太大的情况下是较为有效的方法"。**这段话是国赛论文里写贪心优缺点的最佳模板**。

## 2. 输入与输出

**贪心**
- 输入：问题的**候选集合**（任务/物品/路段/碎片）与**评价准则**（如"单位面积收益最大""距离最近""匹配度最高"）；约束判定函数。
- 输出：一个**可行解**及其目标值；构造过程中的决策序列（可写入论文附录）。
- 关键设计：**排序准则（优先级函数）**。同一个问题换一个排序准则，结果可能差 20% 以上。

**局部搜索**
- 输入：一个可行初始解（就是贪心给的）、**邻域定义**（交换/插入/逆序/±1 调整）、改进判据。
- 输出：邻域意义下的局部最优解与目标值；改进轨迹。

## 3. 算法步骤（伪代码级）

### 3.1 通用贪心框架

1. **定义候选与优先级**：把问题分解成若干"待决策项"，为每项定义一个**可计算的优先级分数** $s_i$（如性价比、紧迫度、边际收益/边际成本）。
2. 按 $s_i$ 降序（或升序）**排序**候选集合。$\text{Solution}\leftarrow\varnothing$。
3. **逐个处理**候选 $i$：
   1. **可行性检验**：若把 $i$ 加入 $\text{Solution}$ 后仍满足全部约束，则加入；
   2. 否则**跳过** $i$（贪心不回退）。
4. 全部候选处理完毕后，输出 $\text{Solution}$。
5. **（重要）多种排序准测对比**：至少算 2～3 种优先级函数（如"按收益""按效率""按紧迫度"），**取目标值最好的那个**，并在论文中做对比表——这是最省力的"提分动作"。

### 3.2 局部搜索（最陡上升爬山 / 首次改进）

1. 输入初始解 $x\leftarrow x_0$，邻域函数 $N(x)$，评价函数 $f$。
2. **循环**：
   1. **枚举邻域**：生成 $N(x)$ 中的所有（或采样的）候选。
   2. 找出其中**目标值最好**的 $x^*$（最陡上升）或**第一个更好**的 $x^*$（首次改进，更快）。
   3. 若 $f(x^*)<f(x)$：$x\leftarrow x^*$，继续循环；
   4. 否则：**当前解即为局部最优，终止**。
3. 输出 $x$。
4. **（强烈建议）多起点重启**：以不同的随机初始解（或不同贪心准则产生的解）重复上述过程 $K$ 次，取最好结果。**"多起点局部搜索"的效果往往比换成 GA/PSO 更好，而且实现只需几行。**

### 3.3 国赛最常见的组合：分阶段贪心 + 局部修正

1. **阶段一**：用贪心确定"大结构"（如先按总运量最小确定各卸点的卡车分配）。
2. **阶段二**：在阶段一的解上，用另一个准则做贪心微调（如"在最优解基础上运用贪心算法求出所用的最少卡车数"——〔原文〕2003B 露天矿）。
3. **阶段三**：对结果做局部搜索（交换/插入）消除明显劣化。
4. **输出 + 与精确解/下界对比**，说明贪心解的质量。

## 4. 复杂度与收敛性

| 方法 | 时间复杂度 | 空间复杂度 | 最优性 |
|---|---|---|---|
| 贪心（排序 + 一次性扫描） | $O(n\log n)$（排序主导）+ $O(n\cdot c_{\text{feas}})$ | $O(n)$ | **无最优保证**；一般有近似比（如集合覆盖 $O(\ln n)$、装箱 $11/9\cdot\text{OPT}+1$）〔推理：属算法理论结论〕 |
| 最陡上升爬山 | 每次迭代 $O(\|N(x)\|\cdot c_f)$；迭代次数通常 $O(n)$ 量级 | $O(\text{解长})$ | **局部最优**（单一邻域） |
| 首次改进爬山 | 每次迭代更快（找到第一个改进即走） | $O(\text{解长})$ | 局部最优，通常质量略差但速度快 |
| 多起点局部搜索 | $K$ 倍单次代价 | $O(\text{解长})$ | 仍然是局部最优，但**命中全局最优的概率随 $K$ 增大而提高** |

**必须写进论文的结论**：
1. **贪心不保证最优**。这是硬事实，论文中不能写"求得最优解"，只能写"求得一个高质量的可行解"。若同时用 LINGO/B&B 求了精确解，可以做对比表。
2. **局部搜索只能保证局部最优**，且**是哪个局部最优取决于初始解**。
3. **贪心的解质量对排序准则极敏感**：换一个准则结果可能差很多；因此**"多准则对比"本身就是一种低成本的改进手段**。
4. **多起点局部搜索在计算量相同的情况下，常常优于单次 GA/PSO 运行**〔推理〕——因为 GA/PSO 的大量评价被浪费在无望区域，而多起点局部搜索每次都保证收敛到局部最优。
5. **复杂度的关键是"可行性检验"** 的代价 $c_{\text{feas}}$：若能增量更新（$O(1)$），贪心就是 $O(n\log n)$；若每次都要重新检查全部约束（$O(n)$），则退化为 $O(n^2)$。

## 5. 参数与调参要点

| 参数 | 推荐取值区间 | 依据 |
|---|---|---|
| **贪心的排序准则** | 至少设计 2～3 种并对比；常见准则：性价比（收益/成本）、紧迫度（截止时间）、边际收益、匹配度、距离最近 | 〔推理〕通用经验；〔原文〕2013B 碎纸拼接即用"（二值匹配）度的贪心算法从左向右" |
| **候选处理顺序** | 降序/升序按准则定；**同分时的打破规则也要指定**（否则结果随数据顺序变化） | 〔推理〕通用经验 |
| **局部搜索邻域** | 交换两点 / 插入 / 逆序 / ±1 调整；可组合（先用交换，卡住后换插入） | 〔推理〕通用经验 |
| **接受策略** | 只接受改进（爬山）；或允许小幅变差（退化为 SA） | 〔推理〕通用经验 |
| **多起点次数 $K$** | 10～200（取决于单次耗时）；每次重启用**不同的贪心准则或随机种子** | 〔推理〕通用经验 |
| **邻域采样** | 邻域 $>10^4$ 时随机采样 100～1000 个候选 | 〔推理〕通用经验 |
| **终止条件** | 邻域无改进（局部最优）；或时间上限；或改进幅度 $<10^{-6}$ | 〔推理〕通用经验 |
| **与精确解对比** | 若规模允许，用 LINGO / `intlinprog` 求精确解或 LP 下界，计算贪心解的**相对偏差** | 〔推理〕；〔原文〕2006A 出版社题即"先应用 LINGO 软件得到全局最优解，而后又引入……**快速贪心算法，并得到了相同的最优分配方案**"——**这是贪心最理想的呈现方式** |

**调参坑**：
- **贪心准则选错** → 结果可能比最优差 30% 以上。**务必做多准则对比**。
- **贪心的"可行性检验"写成 $O(n)$** → 总复杂度从 $O(n\log n)$ 退化为 $O(n^2)$，$n=10^4$ 时慢 100 倍。要增量更新。
- **局部搜索只用一个邻域** → 很容易卡在一个"交换一下就好了"但交换邻域看不到的局部最优（此时应上 VND）。
- **多起点用同一个随机种子** → 所有起点实质相同，等于只跑了一次。
- **忘记记录改进轨迹** → 论文里没有图可画。
- **贪心处理"定和约束"（如总数为常数）时直接跳过** → 会得到不满足总量约束的解；需要设计"补足/削减"的修复步骤。

## 6. 优点

1. **极快**：$O(n\log n)$ 量级，秒级甚至毫秒级出结果；〔原文〕2012B 明确"**时间开销较小**"。
2. **永远给可行解**：不会像 GA/SA 那样出现"跑完发现解不可行"的情况。**比赛现场最怕的就是"跑不出来"，贪心永远不会让你空手而归**。
3. **实现简单、可读性强**：几十行代码，业务含义清晰，评审一眼看懂。
4. **易于解释与答辩**：每一步决策都有明确的业务理由（"优先服务最远的点""优先装性价比最高的货"），非常适合答辩环节。
5. **是元启发式的必要前置**：SA 的初始解（〔原文〕2000B"以所得可行解为初始点"）、VNS/LNS 的起点、GA 的初始种群，都应当由贪心构造。
6. **可作为基准线**：贪心解 + LP 下界 = 一个"我们有理由相信接近最优"的论证，这在论文里比单跑一个 GA 更有说服力。
7. **国赛接受度极高**：全语料中"贪心"共命中 **79 处**，横跨 1998—2023 年，是使用最广的方法之一。

## 7. 缺点

1. **无最优性保证**：贪心可能偏离最优很远（某些问题可达 2 倍以上）。
2. **局部搜索会卡在局部最优**，且是哪个局部最优完全取决于初始解。
3. **对贪心准则敏感**：换一个排序准则结果差很多，而"哪个准则好"往往要试。
4. **不能回退**：贪心早期做错的决定永远无法纠正（这是它和动态规划/精确算法的本质区别）。
5. **对约束的依赖顺序敏感**：某些约束先处理、某些后处理，结果会不同。
6. **单次局部搜索收益有限**：需要多起点或多邻域才能显著提升，而这要付出时间。
7. **构建不良时可能陷入"改了这里坏了那里"**：需要设计好邻域避免循环。
8. **在论文里"看起来不够高级"**：如果全篇只有贪心，技术含量容易被评委低估——**解法是"贪心 + 局部搜索/精修 + 与精确解对比"三件套**。

## 8. 适用规模与适用条件

**适用条件**：
- 问题**有可定义的"局部决策"**（能一步一步做选择）；
- **候选之间近似独立**（贪心的有效性前提）——若候选强耦合，贪心效果会差；
- 需要一个快速可行的初始解（比赛现场的关键约束）；
- 单次可行性检验便宜（$O(1)$ 增量更新最佳）；
- 可接受"近似最优"，或愿意用精确算法做交叉验证。

**适用规模**：
- 贪心：$n=10^2\sim10^7$（几乎无规模限制）；
- 爬山：$n=10^2\sim10^4$，邻域 $O(n)$～$O(n^2)$；
- 多起点局部搜索：$n\lesssim10^3$ 时最有效。

## 9. 不适用情况

- **需要最优性保证的题目**：如小规模整数规划（用分支定界给精确解 + 证明），贪心只会更差且没有说服力。
- **候选之间强耦合**（如"选 A 就必须放弃 B、C"的复杂逻辑）：贪心的逐步决策会做出难以挽回的错误选择；应建模为整数规划。
- **目标函数有多个互相冲突的维度且需要权衡**：单一准则的贪心会严重偏向某一维度。
- **约束复杂且互相牵制**（"贪心构造时无法判断后续是否可行"）：需要回溯/精确算法。
- **目标函数非可加、非单调**：贪心的"局部最优即全局方向"假设失效。
- **凸优化/可微问题**：梯度法/内点法直接给全局最优，用贪心毫无意义。
- **需要"最优性间隙"论证但连下界都没有**：应至少用 LP 松弛求下界。

## 10. Python / MATLAB 实现要点

**Python**
- 贪心核心：`items.sort(key=lambda i: priority(i), reverse=True)`，然后 `for i in items:` 遍历并做可行性判断。**排序键函数是全部设计所在**，务必写得清晰、可复用。
- **可行性检验增量更新**：用累计变量（如已用容量、已覆盖集合）代替每次都重算，把 $O(n)$ 降到 $O(1)$。
- 局部搜索骨架：
  1. `improved = True`；`while improved:` → `improved = False`；
  2. `for (i, j) in neighborhood(x):` → 若更优则执行移动 → `improved = True` → `break`（首次改进）。
- **邻域生成用生成器**（`yield`），避免一次性构造百万候选列表吃光内存。
- 多起点：`best = min((local_search(greedy(seed=s)) for s in range(K)), key=f)`。
- 目标值比较用 `<` 并加容差（`f_new < f_cur - 1e-9`）防浮点死循环。
- 记录 `history`：`history.append((iteration, f(x)))`，画阶梯下降曲线。

**MATLAB**
- 排序优先级：`[~, idx] = sort(priorityVec, 'descend');`，然后 `for k = idx'`。
- 局部搜索用**向量化邻域评价**：把所有候选拼成矩阵一次算完目标（`sum(A.*B,2)`），比循环快 10～100 倍。
- 用 `max`/`min` 的第二个返回值直接拿到最优候选的下标：`[bestVal, bestIdx] = min(candVals);`。
- 多起点：外层 `for s = 1:K, rng(s); ... end`，用 `rng` 固定每个起点的种子以便复现。
- 与精确解对比：调用 `intlinprog` 或 LINGO 求精确解，画柱状对比图（贪心 vs 精确 vs 下界）。
- 国赛老代码风格：多为 `while` 循环 + 显式 `for` 遍历，注意**预分配数组**（`zeros(1,n)`）避免动态增长拖慢速度。

## 11. 国赛论文中的写法与案例

### 推荐句式（可直接套用）

> 由于该问题为 NP 难组合优化问题，精确算法难以在可接受时间内求解，本文首先采用**贪心算法**构造一个可行解：以（单位收益 / 匹配度 / 紧迫度）为优先级对全部候选（任务/碎片/路段）降序排序，依次尝试加入当前方案，若加入后仍满足全部约束则接受，否则跳过。算法时间复杂度为 $O(n\log n)$，可在（$\cdot$）毫秒内得到可行解。

> 考虑到贪心算法得到的解仅为单一邻域意义下的局部最优，本文进一步采用**局部搜索（爬山法）**进行改进：邻域取"交换任意两个（任务/位置）"，反复移动到目标值更优的邻域解，直至无法改进。为降低对初始解的敏感性，本文以（$K=100$）组不同随机种子（或不同优先级准则）重复上述过程，取最优结果。

> 本文对比了三种贪心优先级准则（按收益、按效率、按紧迫度）的求解结果，见表 x，其中按（效率）准则得到的方案目标值最优，为 $\cdot$；三种准则的结果差异达 $\cdot\%$，说明优先级准则的选择对解质量影响显著。

> 为进一步说明所用贪心策略的有效性，本文同时用（LINGO / 整数规划求解器）求得了该问题的精确最优解 $\cdot$，贪心解与其相对偏差为 $\cdot\%$，说明该启发式策略在本题规模下能快速获得接近最优的方案。
