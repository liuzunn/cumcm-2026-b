### 4.4 模板④ 算法设计

**定位**：方案拍板后，产出 `04_算法设计.md`（伪代码 + 复杂度 + 终止条件 + 参数敏感性预案）。
**核心重构点**：**把"算法"与"代码"解耦**。原资料把算法设计塞进"模型求解阶段"（附录二 六），与代码生成混在一起，结果是模型直接跳到代码，中间没有可评审的算法描述。国赛附录要求源程序可运行（格式规范第五条），而算法层若无伪代码，代码级错误无法被定位。

| 槽位 | 本模板如何设计 | 为什么这样设计 |
|---|---|---|
| 角色 | "算法工程师" | 关注可执行性与边界，不关注故事性 |
| 任务 | 伪代码 + 数据结构 + 复杂度 + 终止条件 + 数值稳定性 + 参数敏感性预案 | 六项都是代码前必须冻结的接口 |
| 上下文 | 模板②的决策记录 + 模板③的 clean_data schema | 算法接口必须与实际数据结构一致 |
| 约束 | 每个循环必须有明确上界；每个数值过程必须说明精度与稳定性；禁止"用某个库直接求解"作为算法描述 | 防"调库即答案"（原资料大量"用pulp构建""用scipy.integrate"式描述） |
| 输入 | 必须写明输入张量/矩阵的形状与语义 | 形状约定是编程阶段最常见的返工点 |
| 输出格式 | 伪代码（行号可引用）+ 复杂度表 + 参数表 | 行号可引用，便于模板⑤⑥"按第7行实现" |
| 自检 | 用一个小规模手算例子跑通伪代码 | 手算验证是发现 off-by-one 与符号错误最便宜的方式 |
| 迭代 | 若代码阶段发现伪代码不可实现，必须回到本模板修改并记录变更 | 建立版本链 |
| 工具调用 | ✗ 本模板不产出可运行代码 | 保持算法纯度 |
| 反幻觉 | 复杂度必须给出推导或标注"经验估计" | 防编造 O(·) |
| 评分标准 | 以"可被实现 + 可被检验"为合格线 | 与国赛附录要求呼应 |

- 精度要求：{{例如：结果保留四位小数；时间步 1 s，距离步 0.1 cm}}

# 输出格式
## 一、伪代码（带行号）
要求：
- 显式写出输入 shape 与输出 shape；
- 每个循环写出上界来源（来自数据还是来自精度要求）；
- 每一步的数学式用 LaTeX 写出，与伪代码逐行对应；
- 禁止出现"调用求解器求解"这类空转描述；若确实使用求解器，必须写明"把什么问题交给它（变量数、约束数）"。

## 二、复杂度表
| 步骤 | 时间复杂度 | 空间复杂度 | 依据（推导过程，或标注"经验估计"） |
## 三、终止条件与合理性守卫
| 条件 | 阈值 | 超限时的动作（终止/降级/报警） |
（至少覆盖：迭代不收敛、解越界、数值溢出、约束不可行、时间超预算）
## 四、数值稳定性设计
说明：离散格式与步长如何选择、是否会振荡、用什么判据确认收敛；
必须给出一个**可执行的收敛/精度自检方法**（例如：步长减半后结果变化 < 1e-6）。
## 五、参数表
| 参数 | 含义 | 单位 | 取值/范围 | 来源（题目原文/附件列/公开常数名/【缺失】） | 敏感性预案（变化±10%时如何观测） |

用最小的规模（例如 2 个节点 / 2 个时间步）手算一遍，列出每一步的中间值，
证明伪代码在该样例上给出符合物理/逻辑预期的结果。
## 七、接口冻结声明
- 输入文件：{{文件名与必需列}}
- 输出文件：{{文件名与列定义，若为 result*.xlsx 则给出模板行列对应关系与小数位}}
- 随机性：{{是否含随机算法；若是，种子如何固定}}

# 硬约束
1. 【公共块：反幻觉总则】
2. 禁止把"调用某库函数"作为算法步骤的替代。必须说明该库函数在数学上做了什么。
3. 复杂度若无严格证明，必须明确标注"经验估计"。
4. 参数未经题目给出时，不得给出"典型值"；写【缺失】并进入待确认清单。
5. 不得引入本队环境中不存在的工具箱。
