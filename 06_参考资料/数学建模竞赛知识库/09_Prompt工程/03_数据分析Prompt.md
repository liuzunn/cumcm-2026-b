### 4.3 模板③ 数据分析与预处理

**定位**：产出 `03_数据审计.md` + `clean_data.csv` + `prep.py`。
**核心重构点**：**先审计，后处理；把"是否需要预处理"变成必须回答的第一问**。原资料附录一 L? 有"该数据集是否需要进行预处理"这一问〔原文，附录一 2.1〕，这是好设计；但附录二/六~十一把它删掉了，直接进入预处理方案。同时删除"虚拟下载链接"与"全网自主寻找数据"。

| 槽位 | 本模板如何设计 | 为什么这样设计 |
|---|---|---|
| 角色 | "数据审计员"（不是"建模专家"） | 审计员的产出是可核验的证据，不是方案 |
| 任务 | 判必要性 → 出字段级审计表 → 出处理方案 → 出代码 → 出结论段 | 五步各自有产物 |
| 上下文 | 真实文件名 + 真实列名 + 真实 dtype + 行数 | 原资料把这一步留给用户填【列出数据】占位，实际使用者常常只贴一个文件名 |
| 约束 | **禁止"虚拟下载链接"**；**禁止"全网自主寻找数据"**；缺失值处理必须给"为什么这个字段用这个方法" | 直接删除第 3 节 R3/H2 两条最危险条款 |
| 输入 | 附件文件的真实路径 + 前 5 行样本 | 让 AI 基于真实 schema 而非想象写代码 |
| 输出格式 | 审计表（字段×缺失率×异常率×量纲）+ 处理决策表（字段×方法×依据）+ 代码 + 论文段落 | 处理决策表可直接进论文"数据预处理"章节 |
| 自检 | 核对"处理后数据行数与原始数据的关系是否可解释" | 最常见的静默错误：join 造成行数爆炸或塌缩 |
| 迭代 | 代码报错时，只发报错+相关代码+数据格式，让 AI 先解释原因再给完整修改版 | 借鉴讲义 L85-89〔原文〕 |
| 工具调用 | 输出可运行 Python 代码；**明确声明"我不运行代码"** | 消除 R4 的"自动运行"幻觉 |
| 反幻觉 | 每条处理依据必须引用"审计表中的哪一行" | 防模板化套话（"时序数据用线性插值"） |
| 评分标准 | 不锚定奖项，锚定"能否复现" | 复现性是可判定的，奖项不是 |

- 输出 clean_data.csv 与 audit_log.txt（记录每步做了什么、影响多少行）；
- **不包含任何绘制图片的语句**，绘图统一放到模板⑨。

## 六、论文可用段落（300-500 字）
按"数据来源 → 审计发现 → 处理方法与依据 → 处理前后对比"组织。
每个数字后标注 [来源:审计表第X行]。未在数据中发现的，不得写入。
