## 0. 数据资产表与类型判定

### 0.1 强制回答：本题的官方附件里有没有可直接建模的数据集？

**结论：没有。**

| 判定 | 依据 |
|---|---|
| 官方给出的文件只有 `B题.pdf`、`附件1.docx`（模拟器使用说明）、`附件2.docx`（通信接口说明及编程指南） | 三者均为**规则说明文档**，不含任何数据集 |
| 阶段一表D 已判定"历史数据 / 训练样本 — **不存在**（本题无任何离线数据集）" | 阶段一《赛题分析报告》表D |
| 题目所有关于目标的信息均为"未知" | 题面："目标区域中干扰源个数未知"；附件 2 §1.3："具体有多少个干扰源不会通过接口直接返回"；附件 2 §2.1："模拟器接口不会返回某个干扰源的有效接收半径" |

> **因此，本节不会出现"读入附件 → 检查缺失 → 插补 → 标准化"这条常规流水线。**
> **9 项检查将被逐一映射到下面 5 类真实数据源上判定适用性**——这正是"不得机械套用"的第一层落地。

### 0.3 数据类型判定

| 维度 | 判定 |
|---|---|
| 结构化程度 | **半结构化**（JSON 记录流），非表格型数据集 |
| 静态 / 流式 | **流式**（S1 实时产生且不可重放；S2 是它的落盘副本） |
| 有无标签 | **无监督**：除 S4（自建仿真，自带真值）与 S3（仅演练结束时公布总数）外，**没有任何标签** |
| 样本量 | 每局 10²—10³ 条动作记录；演练次数不限 ⇒ 总量可达 10⁴—10⁵ 条 |
| 是否独立同分布 | **否**：同地点重复读数完全相关（题面附录 2(1)）；样本是**序贯相关**的 |
| **由此直接得出的三条结论** | ① 训练/测试划分、交叉验证、正则化等**监督学习流程不适用**；② 分布拟合与假设检验**只在有明确物理含义的量上做**（如示向度误差），不对构造量做；③ 处理目标是"**在线的证据管理**"，不是"离线特征矩阵" |

## 1. 9 项检查的执行矩阵

> 每一格只填三类之一：**适用**（给方法+判据+来源）/ **不适用**（给理由）/ **部分适用**。
> 「不做会怎样」一列即为提示词要求的"为什么需要"的强制回答。

| # | 检查项 | 适用对象 | 适用性 | 方法 | 判据（阈值及来源） | 不做会怎样 |
|---|---|---|---|---|---|---|
| **1** | 数据完整性 | S1/S2 | **适用** | ① 请求-响应配对率；② 必填字段缺失率；③ `request_id` 唯一性 | 配对率 = 100%；必填字段缺失 = 0；`request_id` 全局唯一（附件 2 §5.3 规定每个新动作必须新 ID） | **无响应**会被当成"无信号"或"动作未执行"，直接改写虚拟时间账与状态机 |
| **2** | 缺失值 | S1/S2 | **部分适用**（只做**分层统计**，**禁止插补**） | 按 `measure_result` 分层统计 `svd_deg` 缺失率 | 预期 direction 层 0%、no_signal/near 层 100%（依据：附件 2 §7.3 明确只有 `direction` 才返回 `svd_deg`） | 若误插补，会把"测不到"伪造成"测到方位"，**直接污染下游可行域账本**，使判空结论错误 |
| **3** | 异常值 | S1/S2 | **适用（3 类）** | ① 圆周量检查；② 越界检查；③ 时间账复核 | ① 差值必须按 mod 360 计算；② `svd_deg` ∈ [0,360)（附件 2 §2.3 明确"返回值仍按 0—360 归一化"）；③ Δ虚拟时间 = Δ距离/5 + 切换(0/1) + 检测(5)/清除(3 或 5)（附件 2 §4.2—4.4） | ① 359.9° 与 0.1° 被算成相差 359.8°；② 越界读数进入楔形计算；③ **程序 bug 无法被发现** |
| **4** | 重复值 | S1/S2 | **适用（两类，必须分开）** | ① 物理重复：按 `request_id`；② 逻辑重复：按量化后的 (x, y, channel) | ① `request_id` 不得重复（附件 2 §5.3：同 ID 同内容返回第一次响应，**不重复推进时间**）；② 同点同频道不得重复（题面附录 2(1)：同地点误差固定，重复检测无信息增益） | ① 虚拟时间被重复累加 ⇒ 平均定位清除时间算错；② 探测次数虚高 ⇒ I-2 的额度分配指数全错 |
| **5** | 数据分布 | S1/S2/S4 | **部分适用** | ① `measure_result` 三类占比；② 误差（读数−真方位）分布 | ② 必须 **100% 落在 ±1°** 内（题面附录 2(1)：误差在 [−1°,1°] 范围内）——这是**语义正确性检验**，不是分布拟合 | ① 无法判断"空频道/超距/朝向外"的比例，I-2 失去输入；② 若误差越界得不到告警，说明环境模型实现有误 |
| **6** | 变量相关性 | S1/S2 | **部分适用** | ① 同点同频道读数的组内极差；② 不同频道间是否相关 | ① 组内极差 = **0**（题面附录 2(1)：重复检测不改变检测误差）；② 不同频道应**不相关**（题面附录 1(2)：不同干扰源的信号互不影响） | ① 无法实证"误差固定"这一关键假设；② 频道串扰（记账 bug）无法发现 |
| **7** | 特征工程 | S1/S2 → 派生 | **适用** | 从原始观测派生**下游真正要用**的量（对齐阶段三 I-3 的账本） | 派生量必须与 I-3 的六个量逐项一致：楔形约束 / 排除集 / 可行域面积 / 可行域直径 / 每频道探测次数 / 距最近覆盖缺口距离 | 下游所有决策（选点、选频道、判空、终止）都失去输入 |
| **8** | 标准化 / 归一化 | 仅决策打分的项 | **部分适用（须严格限定范围）** | 只对量纲不同的**打分项**做无量纲化；用**有量纲常数**归一化以保持可解释性 | 时间除以时间下界、面积除以 πR²（常数来源：阶段一 §5 事实 5 的下界与 πR²） | 若对坐标/距离/角度做 z-score：**距离、角度、凸性全部失效**，几何模块整体崩溃 |
| **9** | 类别变量编码 | S1/S2 | **适用** | 见 §1.1 的编码表 | `channel` 必须作**名义标识符**处理（题面附录 1(1)：按中心频率排序编号，其"大小"无任何语义） | ① one-hot 会丢掉"20 个频道、每频道至多一个源"的结构（附件 2 §1.3）；② 当数值用会引入虚假序关系 |

### 1.1 类别变量编码表（第 9 项的落地）

| 字段 | 类型 | 正确编码 | 错误编码的后果 |
|---|---|---|---|
| `channel` ∈ {1..20} | **名义标识符** | 长度 20 的**索引数组 / 字典键** | one-hot：丢弃"每频道至多一个源"的结构；数值化：引入虚假序关系（频道 7 不比频道 3 "大"） |
| `measure_result` | 名义三分类 | 枚举字典，**仅用于状态机分支** | 映射成 0/1/2 后参与算术 ⇒ "测不到"与"测到方位"变成可平均的数 |
| `action` | 名义四分类 | 枚举字典 | 无意义 |
| `accepted` | 布尔 | 布尔，参与**流程控制** | 当数值参与平均无意义 |
| `clear_result` | 名义二分类 | 枚举字典 | 同上 |

## 2. 数据处理流程

`@text
[S1 在线观测流] ──┐
                  ├─► ① 落盘（S2 自记日志，JSONL，含 request_id 与双时间戳）
                  │        │
                  │        ▼
                  │   ② 完整性门禁：请求-响应配对 / 必填字段 / request_id 唯一性
                  │        │  （不通过 ⇒ 该局作废并告警，不进入后续）
                  │        ▼
                  │   ③ 去重：物理重复（同 request_id）→ 丢弃；逻辑重复（同点同频道）→ 丢弃并计数
                  │        │
                  │        ▼
                  │   ④ 异常处置：角度越界 → 整条剔除（禁止 mod 360 "修复"）；
                  │        │            时间回退 → 剔除 + 记录为程序 bug 指纹
                  │        ▼
                  │   ⑤ 语义检验：误差 ∈ ±1°？同点重复读数极差 = 0？不同频道互不相关？
                  │        │  （不通过 ⇒ 环境模型或程序有误，停下来查，不要往下走）
                  │        ▼
                  │   ⑥ 特征工程：direction → 楔形约束；no_signal → 排除集；
                  │        │            可行域 B_c ← 交 / 差；派生面积、直径、探测计数、距缺口距离
                  │        ▼
                  │   ⑦ 编码与量纲：channel 用索引数组；打分项用有量纲常数归一化
                  │        ▼
                  └─► ⑧ 输出：干净观测表 + 可行域账本 + 质量报告
`@

| 步骤 | 输入 | 输出 | **为什么需要**（不做会怎样） |
|---|---|---|---|
| ① 落盘 | HTTP 响应 | JSONL 日志 | 题目要求"机器狗程序应自行记录指令序列、响应信息等内容"（附件 1 §4.6）；不做则事后无法复盘，也无法填写表 1 |
| ② 完整性门禁 | 日志 | 配对报告 | 连接可能被直接关闭而**没有 JSON 体**（附件 2 §5.3），"无响应"是预期现象；不区分就会把它当成业务结果 |
| ③ 去重 | 日志 | 去重日志 | 重试会复用 `request_id`（附件 2 §5.3），落盘会重复；不去重则虚拟时间被重复累加 |
| ④ 异常处置 | 去重日志 | 干净日志 | 越界读数会让楔形计算给出错误约束；时间回退是 bug 指纹，必须暴露而不是掩盖 |
| ⑤ 语义检验 | 干净日志 | 检验报告 | 这是**唯一能证明"数据语义正确"**的环节；跳过则所有下游结论都建立在未经检验的读数上 |
| ⑥ 特征工程 | 干净日志 | 账本 + 派生特征 | 下游决策（选点/选频道/判空/终止）全部依赖它 |
| ⑦ 编码与量纲 | 派生特征 | 打分输入 | 打分需要无量纲；但几何量必须保持原单位 |
| ⑧ 输出 | 全部 | 三类产物 | 供阶段五实现与论文附录使用 |

## 6. 未通过项的风险与后续动作

### 6.1 最重要的一条：时间账不平**不能靠删记录解决**

- 处理前 **6/33 = 18.2%** 的相邻动作对时间账不平；在剔除 5 条脏记录后仍有 **5/28 = 17.9%** 不平。
- **这说明**：时间账不平是**程序 bug 的指纹**（程序把 `accepted=false` 的 `virtual_time_s=0` 当成了当前时刻，导致后续所有差值错位），**不是脏数据造成的**。删记录只会掩盖症状。
- **正确动作**：回到程序侧修——记录虚拟时刻时**只能取最近一次 `accepted=true` 的响应**（附件 2 §4.1 原文）；并在每局结束时用"**Σ各动作耗时 = 末条记录的 `virtual_time_s`**"做一次全账复核。
- **数据侧的兜底**：在质检报告里把"时间账不平条数"作为**每局必报指标**；一旦非零，该局数据**标记为可疑**，其统计值不进入论文正文。

### 6.2 其他风险与后续动作
